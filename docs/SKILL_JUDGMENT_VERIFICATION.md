# Skill 最终判断核验契约

2026-10-11，ARCH-03，版本 `skill-judgment-v1`。工程与自审证据见[记录 179](reviews/2026-10-11-implementation-179-final-skill-judgment-verification.md)；任务状态以[当前台账](CURRENT_TASKS.md)为准。

## 1. 为什么增加这一层

`protocol_deviation` 和 `off_label_check` 都先通过 Harness 取得已核验的条款，再由模型生成比较结论。原代码只校验结论枚举和条款编号，没有核验比较是否成立。例如“允许第 8～10 天访视”与“第 9 天访视”，可能得到引用正确、结论相反的结果。第一阶段证据核验不能证明第二阶段业务判断正确。

当前路径：权限与输入校验 → Harness 检索及条款核验 → 结构化候选 → 本地严格契约与既有安全规则 → 最终比较核验 → Registry 最终安全检查 → 返回结果。核验器在 `verification` 包，两类 Skill 通过同一个接线函数调用；没有新增检索入口、模型供应商连接或独立预算。

## 2. 四项必须分别支持

| 字段 | 核验内容 |
| --- | --- |
| `conclusion` | 结论和偏离类型能否由所引条款与原始观察共同推出 |
| `rationale` | 完整理由是否成立，保留数字、单位、频次、否定、人群、条件、例外及共同必需内容 |
| `clause_relevance` | 条款是否真的覆盖、适用于这项判断；合法编号不能代替语义支持 |
| `observation_grounding` | 是否准确使用用户所述事实，有无添加、颠倒或把事实当成文件规则 |

每项均使用 `supported / not_supported / contradicted`。**所有维度的四项都必须 supported** 才能业务完成；判断未涉及也须核验其不确定性及理由。某个维度失败时，当前实现不返回其他维度作为已完成判断。

用户观察仅作假定前提：核验不证明真实患者事件发生，也不把观察加入文档证据或引文。确定判断的语义输入只包含所引条款；不能用未引用的正确条款补救错引。不确定判断可以查看当前提供的全部已核验条款，范围仍限本次材料。

## 3. 规则与模型的分工

规则检查引用索引、必需引用、非空理由和偏离枚举/类型一致性。第二阶段回复由本地类型契约再次校验，不能只相信供应商 JSON Schema；bool、字符串或小数索引不转成整数，越界引用不静默删除，理由不截断成一段看似合法的文本。缺失、重复或未请求的 off-label 维度、语义判定缺项/重复项/未知项及截断回复均失败关闭。

另有两类**仅拒绝矛盾、不自动证明正确**的窄规则：

- 单一完整条款的访视日区间，与单一明确访视日比较。支持测试中的简体句式和原审查英文句式，包括区间两端；明确反转拒绝。
- 单一完整条款的每日最高质量剂量，与明确的每日质量剂量比较。复用既有元素提取/单位归一；超过上限仍声称 within_label 时拒绝。

两类规则只在完整句式匹配时使用；带条件、例外、多个规则、不同比对锚点、体重/面积剂量、不同量纲或未覆盖的表达交给模型。不因单个不同数字就认定矛盾。规则不修改 `verify_claims` 的 ADR-0011 策略或历史评测口径。

语义核验沿用配置中的 `judge_model_id`，新增用途 `skill:verify_judgment`。每次 Skill 最多一轮批量最终核验（最多四项）；外层已有幂等重试可能重新执行，所有尝试继续共享预算。缺少判定模型时，不能用关键词或文字重叠宣称最终比较已获支持。

**这是新的业务比较任务，不代表已有模型已在这类任务上校准。** 假网关测试只证明调用、数据边界、规则和拒绝路径；真实医学语义正确率、误拒绝、费用及延迟另须预登记与付费授权。

## 4. 结果和失败处理

| 情况 | Skill 业务状态与载荷 |
| --- | --- |
| 全部核验支持 | `completed`，保留原结论/理由，并附核验摘要 |
| 任一核验无支持、引用不足或未配置语义判定 | `insufficient_evidence` + `unsupported_conclusion`；偏离改为 undetermined，或各用法维度标记 not_addressed；清除未经支持的理由与结论引用 |
| 任一核验明确矛盾 | `escalated` + `unsupported_conclusion`；同样清除错误结论、理由及结论引用，保持原安全基线的矛盾升级边界 |
| 回复损坏、截断、超时或供应商错误 | 既有 Registry 异常路径；`system_failure` 或实际的预算耗尽原因，不回退为候选结论 |
| Token、费用、期限或租约不足 | 原共享执行保护拒绝继续调用，不新开额度、不返回未核验结果 |
| 候选包含个人医疗建议等禁用内容 | 原安全规则拒绝并由 Registry 清除载荷；无需额外付费判定该候选 |

无支持载荷仍可包含第一阶段已核验的条款与引文，便于核对，但这些不是对被拒绝业务判断的背书。off-label 的 `not_addressed` 在失败载荷中表示当前无已核验比较结论；**不能据此断言完整说明书没有规定**，须结合业务状态和 reason_codes 读取。

异步 Task 的 `TaskStatus.completed` 表示任务执行已结束；其 `result.status` 与 Trace outcome 才表示业务结论是否完成、证据不足或已升级。规则矛盾的任务可以执行结束，同时业务状态为 escalated；没有修改这两个现有状态层级。

## 5. 版本、权限与追溯

两类结果新增可空 `judgment_verification`，包含核验版本、输入 SHA-256、配置判定模型、逐项四类判定、引用索引及确定性拒绝代码。旧结果可以反序列化为 None；None 不表示通过。严格客户端需要接受新字段。修复保留原 Skill 标签和默认模型，是代码版本控制的行为修复，不发布新的 Prompt 或策略指针；历史结果不会自动补判或改变。

SHA 绑定原始观察、候选判断/理由、选定索引和全部实际条款，便于后续完整输入核对；哈希本身不是恢复材料。最终核验调用继承 Trace/run/attempt、Token/费用与总期限。`skill.final_verify` 遥测只发送版本、数量及结果元数据，不发送观察、候选理由或条款正文。

ARCH-06 仍须补异步任务完整证据/内层核验审计与受限载荷责任，ARCH-07 仍须补完整输入和原条件复现。本轮没有宣称这些已完成，也没有改 ACL、冻结数据、指标阈值或生产激活规则。

## 6. 五类 Skill 的核验范围

| Skill | 本轮范围 |
| --- | --- |
| protocol_deviation | 新增最终业务比较核验 |
| off_label_check | 新增逐维度最终业务比较核验 |
| label_query | 原 Harness 的最终 claim-citation 核验，做兼容回归 |
| citation_verification | 原引用/陈述支持核验，做兼容回归 |
| ae_extraction | 原叙述引用定位与因果表述拒绝，做兼容回归；没有新增医学判断或声称 quote 匹配能证明全部提取 value 语义正确 |

五类共同矩阵通过不等于五类全部医学语义已经正式验收。新最终判定的真实校准、独立人工复核、正式 Skill 质量及容量仍为外部证据；后续 AGENT-05/09 必须继续逐类核对真实最终载荷。
