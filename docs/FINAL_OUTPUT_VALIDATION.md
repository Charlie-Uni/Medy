# 最终输出授权与事实复核

日期：2026-10-12；ARCH-15。实现和自审证据见[记录191](reviews/2026-10-12-implementation-191-final-output-validation.md)，执行顺序见[台账](CURRENT_TASKS.md)。本契约适用于当前 Ask、五类异步 Skill、Task 结果读取和四个 MCP 工具；不表示动态 Agent 或自进化已实现。

## 1. 为什么需要终检

检索时有权读取，不保证模型结束时仍有权返回。Python 中已取得的 Evidence 不会随数据库撤权自动消失。同一 READ COMMITTED 事务可以重新读到变化，但一次 SELECT 后还可能发生写入。因此需要重新检查，也需要保护从检查到结果及审计提交的区间。

此次保留原请求事务，不引入连接池或拆分模型期间的事务。ARCH-12 的性能方案和限制仍见[事务评估](REQUEST_TRANSACTION_PLAN.md)。

## 2. 检查哪些事实

| 边界 | 最终复核 | 失败行为 |
| --- | --- | --- |
| Ask | 再验 Bearer，读取当前目录的 active、部门、roles、scopes；原日期/历史模式下回查完整 Evidence | 移除答案，升级或拒绝；不重跑模型或删除必要证据继续回答 |
| 五类 Skill 完成 | 当前目录身份；内层 Harness 的全部支持证据；实际 evidence/doc_type lookup 的正、负观察结果 | 回滚成功事务，以失败 attempt 和审计报告；不能写 completed 结果 |
| Task GET、幂等 POST、retry 返回已存结果 | 完成时绑定的身份、QueryContext、完整 Citation/哈希/状态，以及 lookup 元数据 | 不返回已存正文；不根据今天的数据反向编造当时证据 |
| MCP search | 当前身份；首次搜索准备好的全部返回 Evidence，精确比较已准备的 snippet/Citation | 不再检索或翻译；工具错误，保留已发生用量 |
| MCP get/verify/list | 当前身份；重新读取并精确比较结果和来源/生效窗口/parse/integrity/hash 元数据 | 不返回旧内容；raw 工具的原有语义保持 |

Evidence 复核沿用事实面七项规则：RLS 可见性、状态、日期窗口、来源 verified、parse trusted、重算内容哈希、原文 span 存在；完整 Citation、文本、两个哈希、状态和 historical 标记须一致。全部参与判断的块都要复核，不能只看最终引用列表。事件叙述仍属于用户输入，不被标记成数据库文档事实。

Lookup 绑定记录实际查询的 ID 与原结果，包括空结果。这样“某引用不可见”的判断在后来获得可见性时也会失败关闭。绑定只有身份、日期、引用、哈希和类型等元数据；不增加公开 TaskResponse 字段，也不把证据正文写入遥测。原有 TaskResult 和受限审计材料的存储边界不改变。

## 3. 检查到提交的竞态

Migration 0026 引入数据库范围的 advisory 读写栅栏：最终输出持有共享事务锁，principals、document_acl、documents、source_objects、chunks、chunk_spans 的普通 INSERT/UPDATE/DELETE/TRUNCATE 在 statement trigger 中取得排他事务锁。

1. 写方先持锁：终检等待；写方提交后，后续 READ COMMITTED 查询读取新事实。锁等待最多 1 秒，超时失败关闭。
2. 终检先持锁：普通事实修改等待，直到结果及审计事务提交或回滚。锁不覆盖模型调用、翻译或本地推理等待。
3. 使用 READ COMMITTED；REPEATABLE READ 的旧快照不准取得输出栅栏。执行角色必须受 ACL/RLS 约束，不借用 admin DSN 复核。
4. MCP 的事实只读连接和身份/审计 app 连接必须指向同一运行中数据库；app 栅栏保持到只读连接关闭、审计写入及 app 提交结束。

**授权线性化点是成功审计/结果提交。** 之后发生的撤权不能撤回已经提交并可能正在网络传输的结果；后续 Task 读取必须重新检查。此契约没有承诺“撤权后的网络中绝无旧字节”。

共享全局锁是一种保守的正确性实现，普通知识写入之间也会序列化。尚未测量真实并发容量影响，不能据此声明提速。后续按事实库规模和实际写入争用评估更细粒度的版本栅栏，必须保持相同输出约束。

## 4. 超时、回滚与用量

Ask/Skill 的终检与成功审计有额外 5 秒上限，并继续取外层执行剩余时间的较小值；不扩大已有总时限、Token 或费用上限。MCP 同样限制最后的事实复核与审计。SQL 使用 DeadlineConnection；失败的终检由 savepoint 回滚，正常失败审计保持可用。

修复了 DeadlineConnection 的首次 SQL 边界：未开始的隐式事务先 BEGIN，之后使用 savepoint，不能由逐语句包装器提前提交。真实 PostgreSQL 回滚测试和 Task 审计故障测试覆盖此行为。

成功结果和 Trace、配置启用时的加密材料仍须原子提交。锁失败不重跑模型；模拟已知费用和 Token 在失败审计中保持。若总期限耗尽或审计本身不可用，继续失败关闭；已有逐调用持久回执负责保留已发生费用，不承诺此时一定有完整业务 Trace。数据库连接/提交仍受既有驱动和服务器期限约束，不承诺对任意不合作插件通用强杀。

## 5. 数据库升级与旧任务

先备份，执行 0026，再核对事实/权限/策略/账本内容摘要、索引计数和事实库身份。备份属于本地受限材料，不提交到 Git。ready 检查验证栅栏函数、启用的六个事实触发器和 tasks.output_binding 列；缺失时不报告可服务。

迁移只增加私有结果绑定和触发器，不修改原结果正文。历史 completed Task 没有原始绑定时，新接口不返回其结果。原数据和审计继续保留；不能从当前数据自动补签或冒充原始证据。需要恢复读取时另做有证据的审计恢复方案，或在明确费用授权后重新运行。不能为了兼容关闭终检。

回滚代码必须与数据库版本配套。0026 downgrade 删除栅栏和绑定列，会丢弃新增绑定；先停止使用新代码并保留备份。因为安全修复被移除，回滚不算安全门通过。

## 6. 信任与未交付边界

- 栅栏覆盖普通 DML。可信迁移/超级用户能禁用 trigger、改变角色或修改函数，此类运维操作不属于租户威胁保证；测试中模拟物理损坏只使用拥有的临时库。
- 终检读取数据库完整性状态，不重新下载官方 PDF，也不在每次输出时重新计算所有原始文件哈希。
- 固定 stdio 开发身份可沿用原无目录行的开发模式；真实 Bearer 和已有目录行不得借此绕过停用/变更检查。
- 工程测试使用合成事实与脚本网关，0 托管调用。真实模型质量、容量、第二独立人工、未见盲测仍按原任务登记；此修复不替代质量或发布门禁。
- 原条件恢复、Task/MCP 回放、MCP 受限完整材料、Agent 行动/profile 契约仍待对应任务交付。
