## 7. 每轮完成定义

**每次工作，包括代码、文档、实验、部署和台账更新，都必须自审核。** 开始时登记任务 ID、范围、依赖、固定条件和通过证据；结束时在 `docs/reviews/` 保存本轮记录，并链接回台账。模板见[阶段表 §3](ITERATION_STAGES.md#3-每轮强制自审记录)。

流程：`READY → IN_PROGRESS → REVIEW → DONE`。受阻转入对应 `BLOCKED/HUMAN/PAID` 并记录原因；不把等待当作通过。自审至少核对需求、正确性/失败路径、权限/数据、预算/取消、追溯/版本、验证证据、状态/文档，各项填写“通过 / 不通过 / 不适用及理由”。有缺陷先修、复测、再审核；影响本轮结论的问题未解决时不得 DONE。文档轮核对链接、编号、状态与前后约束即可，不机械要求与风险无关的全量代码测试。

代码轮交付可运行行为、必要的正常与失败/并发/权限回归、复现命令/退出码/跳过原因、已知限制及回滚方法；架构缺陷应保留原反例。是否需要全量检查按本轮影响和仓库门禁决定。正式医学质量、性能与发布状态必须有各自运行证据；自审核不等于独立人工复核。

不得隐式改变阈值、分母、模型、gold、ACL、发布策略或安全规则；不得把数据库预算或旧授权当作新付费运行授权。遇到确需决定的问题，先给具体材料和建议，再交用户决定；可继续无关已授权工作。当前未提交改动按功能边界处理，核对工作区归属，不覆盖其他工作；提交/推送按当次任务范围执行，继续排除 `output/pdf` 和本地临时产物。
