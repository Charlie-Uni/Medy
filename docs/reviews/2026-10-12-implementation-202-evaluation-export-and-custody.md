## 1. 这一步做了什么、为什么

[记录201](2026-10-12-implementation-201-evaluation-isolation-primitives.md)已提供 manifest、输入投影和暴露账本，本轮补“什么结果可以从保管端出去”。只导出固定完整集合与预登记指标的汇总，防止缺失失败行、运行中揭盲、小切片或改行复用旧授权。按[隔离契约v0.3](../agent/EVALUATION_ISOLATION.md)执行，不把这一模块当作新评分器或模型质量提升。

[aggregate.py](../../src/medops/evals/isolation/aggregate.py)实现：

1. 显式 ExportPolicy：固定指标 UUID、轮数和三个最小数量，不设正式阈值默认；合成 20/2/5 只是 canary，未代替至少200未见任务要求。
2. ReleaseGrant 绑定集合、完整运行锁、策略和具体行结果摘要；holdout 只允许保管/盲测审核角色，开发/生成/runtime/普通验证角色拒绝。grant 由后续可信服务端签发，不从模型参数接受授权。
3. 两臂全部任务/指标/轮次的矩阵完整检查，重复、额外、缺失和未完成批次拒绝；unknown 留分母。三轮按重复执行计数，唯一任务不乘三。
4. 非空结果格的唯一任务/登记家族不足，整个指标两臂一起抑制，不留下可反推补集。其他合格指标仍可导出；不输出抑制原因、逐题信息或私有行结果摘要。
5. 固定 PublicSummary，只输出允许元数据和合格总计，资格固定 unknown、真实部署隔离/第二人工固定 false。模型都禁止未知字段，关键操作重新校验复制对象。

两套 CLI 仅接受公开合成自检选项，旧 `--self-check` 九项保留；新 `--export-self-check` 六项检查完整批次、正文出口、部分批次拒绝、稀有格双臂抑制、改行授权拒绝及开发角色拒绝。没有任意文件输入、模型或服务连接。

另完成[保管部署提案v0.1](../agent/EVALUATION_CUSTODY.md)：推荐所有者控制开发助手无凭据/管理权的独立环境；也可暂缓真实盲测，继续公开准备。细列真实身份、query/gold凭据、评分器只读、日志/缓存/模型出口、审计先于披露、可信头/恢复及部署正负检查。仍待所有者选定，未创建账号/购买资源/部署。

## 2. 发现的问题与修复

- 首轮 lint 原文：`B023 Function definition does not bind loop variable metric`。辅助函数在循环内读取 metric，虽当前即时调用仍有潜在绑定风险；移到循环外、显式传参数，未使用豁免，全量 lint 复测通过。
- 增加 CLI 后 lint 原文：`I001 Import block is un-sorted or un-formatted`。整理 import，全量复测通过。
- 自审发现复制坏值在校验前序列化，Pydantic 警告可能带回私有内容；现在 `warnings=False`，随后重新校验，序列化/验证 ValueError 统一转换固定 IsolationError。异常链不对外输出。用含 gold canary 的坏 UUID 和不可序列化对象验证：无私有警告，固定错误码，均通过。
- 统计范围审查发现容易误把汇总计数当配对改进证据；代码/文档明确没有 CI、新 rubric 或独立性证明。N/A、逐 claim、时延等不在当前全任务二值矩阵内；后续必须登记适用集合及分母，不能拿 unknown 顶替不适用或改变旧评分口径。
