## 为什么先补预算与失败记账

旧工具仅传单次 `--max-budget-usd`，成功返回后才记录费用。多个批次、失败或无效 JSON、重试、进程重启都会让只加成功结果的总数失真。本轮增加 `medops.evals.review_budget.ReviewBudget`：

- 一份账本绑定本次授权和全部四批输入；固定总上限，改变范围或总额拒绝沿用。
- 文件锁使共用账本的调用串行；调用前写入预留，原子替换并 fsync。未结算的预留阻止后续调用；崩溃不会默默丢掉占用。
- 调用成功、非成功、错误模型、无效意见均计费；CLI 未提供可信费用时标 unknown_charge，停止继续花费。
- 实际费用用 Decimal 向上取整到微美元；重复结算拒绝。额度不足不发请求，无自动重试；超过单次预留后也停止，检查 CLI 限额语义。
- 第一题单次预留 0.25 USD，实际为 0.17402875 USD。后续预留 1.25 USD，为长推理提供更充足的单次空间，返回后释放未用额度；总授权仍为 5 USD。这是调用调度和核账机制，不是供应商账单硬封顶的验证。
- 原始 CLI stdout/stderr 保存在忽略目录，文件权限 0600；追踪元数据保存其哈希。非成功响应先提取费用，再返回安全错误码，不将整段 CLI 正文打印进异常。

CLI 当前通过 Claude 订阅登录。这里的 USD 是 CLI 报告的用量估算，不能直接表述为新增信用卡扣款；本轮没有查询或修改账单与自动充值设置。
