## 1. 核对了什么

生产连接由`ProductionRuntime.connection()`新建并持有一个事务。Ask从认证到Harness到审计均在其中；Task领取、调用前查lease是独立短事务，业务和最终写入仍长事务。检索工厂把调用方连接传入；节点幂等claim、attempt、complete/fail也在业务事务。

不能仅添加autocommit、提前close或在数据库池中随便释放：这些操作会改变SET LOCAL部门、幂等claim可见性、事务失败/恢复、审计原子性及最终权限事实。现有持续费用账本的短事务不属于本轮需重写范围。

本轮未改`src/`、默认模型、发布策略、RLS、冻结数据/gold、计分阈值和任何生产事务接口。运行工程核验不表示问答质量、安全门禁、Agent或自进化已交付。

## 3. 决定与为什么

**当前保留生产每请求事务；不接线phased原型、不加入Pool。**

无限额情形中，phased减少连接占用时间但多了一次建连及独立提交，未证明端到端/吞吐收益。人为4槽时能够释放等待期间的槽，吞吐提高且排队尾延迟降低；该限制是诊断实验设定，不是现网资源或已有连接池。单点server计数不等于真实高峰余量。

原AR12要求“测量有收益再实施”；本轮交付的是有条件的评估决定。实际连接瓶颈、最终授权栅栏及恢复契约未具备前，不承担拆分实现风险。将来对实际流量/部署证实连接受限，可按方案重开性能实现，分别测只加池、只拆事务、组合。所有真实模型运行继续按次授权。
