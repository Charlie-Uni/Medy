# 记录 135：回放安全输入固化与来源运行校验

日期：2026-10-08。阶段 1 / OPT-12。本轮自审通过，正式新回放与阶段验收仍待真实运行。

## 发现的问题

旧回放冻结了题目和 expected，却未保存执行所需的完整安全样本。运行器仍从当前草案/撤下档案读取 ACL、攻击、Skill 参数和预期，可能把“冻结题目”与另一份执行输入混用。只读比较 replay-v3 的 170 条安全项，实际发现 **ss-0125 的 expected 已漂移**，详见[原值和现值](2026-10-08-implementation-135-legacy-safety-drift.json)。

导出器还有两处相关问题：安全来源版本可在项内更新，manifest 却写死 `safety-v1-provisional`；同名输出目录可被覆盖。这些问题会削弱复现实验和定位误判的能力。

## 修改

- 新 `embedded-safety-sample-v1`：回放安全项携带完整冻结样本和 canonical SHA-256，保留 ACL、canary、Skill 输入/scopes、历史参数和预期。运行前核对内外字段、ID、来源版本和哈希。
- 新主集/安全运行逐行记录 `sample_input_sha256` 与实际 `versions`。导出要求完整样本集合、原 query/部门/语言/切片一致，主集类型/预期/证据组一致，安全检查与 passed/failed_checks 一致。缺失或混用在创建输出目录前拒绝。
- 两个来源均须通过冻结文件校验，并有精确 dataset binding 和一致的结果数据哈希；主集还须匹配 `main-outcome-v2` 的运行绑定。导出保存来源 manifest、binding、results、rows 的哈希。
- 安全来源版本统一取实际 manifest。取消导出过程中的全局版本变量修改，避免同进程多次导出互相污染。新输出拒绝覆盖，筛选人数或标签分布不足时报明确错误。
- 新安全执行完全取消读取当前草案。历史 replay-v1/v2/v3 保留检查、报告、估价和 `--skip-safety` 主集诊断；包含安全项的新执行会在模型/数据库工作前拒绝，并要求新的自包含回放集。跳过安全不能算发布门禁通过。
- 更新 [spec-r1 v0.2](../../evals/replay/SPEC.md)。这是输入完整性修订，未改变原业务门槛、样本要求或旧成绩。

没有生成正式 replay-v4，没有为历史运行补造新样本哈希，没有付费调用。本轮测试临时创建的回放都是隔离 fixture。
