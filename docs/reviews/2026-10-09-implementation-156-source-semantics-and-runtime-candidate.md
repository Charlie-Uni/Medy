# 记录 156：来源语义契约与运行时候选

日期：2026-10-09。状态：**EVAL-13 工程范围完成；`source-constraint-v1` 已接线但默认关闭；正式答案级回归与发布决定未执行。**

## 1. 目标与边界

本轮落实两个彼此独立的判断：

1. 评测侧判断回答是否引用了问题真正要求的来源；
2. 运行侧在高置信情况下把检索限制到调用者实际可见的目标文档。

来源身份与事实覆盖分别计分。`required_source_groups` 判断文档身份，`required_gold_groups` 判断事实证据：两者都是组间全部必需、组内任一即可。命中正确文件不能证明答案完整；引用事实相同的其他文件也不能满足明确点名的来源。

没有修改冻结的 `main-v5-provisional`、历史运行标签、分母、gold、ACL、模型或正式门槛。没有模型调用或新增费用。来源契约仍为 provisional，因为当前没有第二独立人工。

## 2. 版本化评测契约

新增 `evals/source_semantics/main-v5-provisional.json`，逐条绑定：

- 主集 ID、版本和 dataset hash；
- 样本 ID 与 query SHA-256；
- 文档 key、source hash 与 version label；
- 来源角色、必需来源组、被引用但不是目标的提及及裁决依据。

共 34 条：

| 类别 | 条数 | 含义 |
| --- | ---: | --- |
| `named_product` | 6 | 明确产品仿单，只接受该产品适用版本 |
| `named_document` | 3 | 明确文件，不接受同句转载替代 |
| `named_document_version` | 5 | 文件、发布方和版本共同约束 |
| `equivalent_carrier` | 2 | 经复核的窄范围等价载体 |
| `host_document_with_reference` | 12 | 问的是宿主文件怎样引用或讨论另一文件 |
| `embedded_original_text` | 4 | 问的是合订文件承载的旧版原文 |
| `relationship_statement` | 2 | 问文件间关系，不能硬选第一次出现的编号 |

`evals/harness/tools/source_check.py` 从真实运行保存的 answer-review snapshot 读取回答实际引用的文档，再用 source hash 计分。缺运行行、缺快照或未完成材料保持 `pending`，总 rate 为 `null`；工具不会把缺材料当成功，也不回写旧的主集成功标签。

## 3. 运行时候选

新增 `source-constraint-v1`，作为 `retrieval_params/hybrid.source_constraint` 的布尔发布参数，仓库默认值为 `false`。启用时：

1. 在调用者身份绑定、RLS 生效的连接中只读取其可见 active 文档；
2. 解析产品名、ICH/GVP 编号、发布机构、明确标题、版本限定和已复核的窄范围等价载体；
3. 同时把词法和向量检索限制到解析后的文档 ID；
4. 缓存键使用包含规则版本的新 `retrieval_version`，缓存命中仍做事实平面复核及来源过滤；
5. 点名来源不可见时返回通用的空证据结果，由现有安全节点升级为 `insufficient_evidence`，不调用翻译或回答模型，也不披露禁用文档标题、部门或是否存在。

该候选不把所有编号都当目标。讨论、采用、引用、`as cited in`、合订本、上下文“本文件”和文件关系均有单独分支；无法确定上下文宿主身份时不施加强约束，保留现有检索行为。

## 4. 实现中发现的错误与补救

| 现象 | 原因 | 修复与复测 |
| --- | --- | --- |
| Addendum I 同时命中 Addendum II | 标题用普通子串判断，`I` 是 `II` 的前缀 | 优先精确 `document_key`，标题回退增加罗马数字边界；只剩 Addendum I |
| FDA 的英文 “discussion of ICH E6” 被当成直接询问 ICH E6 | 讨论提示只覆盖中文且词序过窄 | 增加英文 discussion 模式；该题不再错误弃答 |
| “本文件…ICH E1” 把 E1 当目标 | 运行时没有会话中“本文件”的文档身份 | 将明确上下文指代视为不可安全硬约束；保留普通检索 |
| FDA 草案“采用 ICH E3(R1) 定义”误选 ICH 原件 | 采用模式未覆盖 `采用了` 及英文倒装问法 | FDA 宿主与 adopt/采用组合识别为引用意图 |
| 穩壓/胃所樂题额外命中樂寶寧 | 旧标题抽取把“樂寶寧 ”丢成通用 key `膜衣` | 严格约束层拒绝通用剂型 key，仅接受实际产品名 |
| E6(R3) 同时选中主指南与 Annex 2 | 两份标题共享相同 ICH code | 未点名 Annex 时排除带 Annex 限定的 companion 文档 |
| `uv run` 找不到 ruff/pytest/mypy | `uv run` 使用的环境没有 dev 工具；仓库规定使用非点目录 `venv/` | 改用 `venv/bin/...`，不把环境错误记为代码缺陷 |
| 首次 `make check` 在 format-check 停止 | 两个新增 Python 文件尚未应用仓库 ruff formatter | 格式化这两个文件后从头重跑，完整门禁通过 |

这些修复不是根据最终回答“调到能过”为止：每条规则同时由目标题与引用/关系反例约束，运行参数仍保持关闭，等待独立的答案级对照。

## 5. 验证结果

- 来源契约自身：34 条全部绑定当前冻结 query、corpus 身份和 gold 来源；类别计数与清单一致；
- 真实 `medops_v2`、应用角色和部门 RLS：PV 127、CO 81、MA 125 份可见 active 文档；34/34 契约均无错误来源或错误 missing；
- `ss-0090`（CO 请求 PV 的 ICH E2F）和 `ss-0096`（MA 请求 CO 的 ICH E14）：均得到 `required=true`、`missing=true`、零文档 ID，输出不含禁用标题；
- 定向单元测试：来源契约、解析、组语义、发布参数、版本哈希、双通道文档范围、缓存与 API/MCP 相关路径 **83 passed**；
- 解析与契约合并回归：**48 passed**；
- `env -u DEBUG -u PYTHONPATH make check`：**1690 passed、70 skipped、1 条既有短 HMAC key warning**；ruff、435 个维护文件格式、188 个源文件 mypy、评测审计与 schema 漂移均通过；
- 评测审计只保留 4 条已登记警告：2 个 unmappable gold、历史 replay 使用旧安全集、第二人工 pending、无未见盲测集。

机器摘要见同名 verification JSON。

## 6. 已知限制与下一门

- 规则只覆盖高置信模式；“本文件”等上下文指代在没有会话来源身份时不会强制过滤。
- 当前只以可见 active 文档解析。历史版本查询在正式启用前必须单独验证，不能由本轮结果推断。
- 34 条均来自已参与开发的现行主集；它们是回归集，不是未见盲测集。
- 零费用解析测试证明路由选择与权限边界，没有证明最终答案质量。`ss-0090/0096` 与正常题的真实答案级对照、误拒答率、时延和费用仍待一次明确授权的付费运行。
- 在正式对照和人工发布决定前，`source_constraint` 保持默认关闭，不能把本轮记成生产缺陷已经发布修复。
