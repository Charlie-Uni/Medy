# 实现记录 122：模型路由——新的可发布目标 `model_route/answer` 与按费用计的门禁档位（零费用部分）

日期：2026-10-05。决策人对「模型路由按时延 / 费用而不是 token 来评」「全部添加」答复「可以」。本记录只有代码、测试与候选文件；没有模型调用，费用 0。试跑（约 1.3 USD）开跑前另行征得同意。

## 1. 先看路由能碰到多少问题

用本机的意图规则（`medops.harness.intent.classify`，不调模型）给回放集 614 题分类：

| 意图 | 题数 | 占比 |
| --- | ---: | ---: |
| general_qa | 512 | 83% |
| label_query | 87 | 14% |
| protocol_deviation | 13 | 2% |
| ae_extraction | 2 | 0.3% |

记录 91 设想的是「简单意图（label_query）走小模型」。按这个分布它只覆盖 14% 的问题；作答调用约占单题费用的三分之二，所以最多省约一成费用，时延也只改善这 14%。因此目标做成**每种意图单独指定作答模型**，先用一个诊断候选量出小模型在各类问题上的质量，再决定路由范围。

## 2. 实现

- 新的可发布目标 `model_route/answer`，diff 形如 `{"<意图>": {"from": "<模型>", "to": "<模型>"}}`。可路由的意图：label_query、general_qa、ae_extraction、off_label_check、protocol_deviation、citation_verification（high_risk 与 unclear 本来就不进作答节点）。允许的作答模型：gpt-6-sol、gpt-6-luna（ADR-0010 同一厂商的锁定 ID）。
- 作答节点按当前问题的意图取模型，未列出的意图沿用锁定的 gpt-6-sol。**判定模型不路由**，校验仍由 gpt-6-sol 完成（ADR-0011）；Skill 的结构化调用不受影响。
- 生效的路由写进 `model_config_version`（后缀 `;route=意图:模型,…`），作答节点的操作键含实际模型，换模型不会复用另一模型的已存执行。
- 接线：API 运行时、安全运行器、全量运行器、回放运行器；回放运行器打印的两臂生效配置里多一项 `answer_models`。
- 门禁新增档位 `spend`：目标是每道主集题的模型费用（USD），候选须至少低 25%（沿用基线对 token 目标用的同一个比例），总体质量下降不超过 1 pp，切片与安全规则不变。时延由运行器报告、不进门禁——回放的两臂不在同一负载下运行，比不出可靠的差。阈值在任何测量之前写定。
- 价格（网关价目表）：gpt-6-luna 每百万 token 输入 0.10 / 输出 0.50 USD，gpt-6-sol 2.00 / 10.00。

## 4. 测试

- 策略加载器：路由的意图 / 模型白名单、空 diff 与「什么都没改」被拒、版本后缀、受支持目标集合。
- 作答节点：路由后作答调用换模型、判定调用仍是 gpt-6-sol、其他意图不受影响、操作键随模型变化。
- 门禁：`spend` 档位通过 / 省得不够 / 质量下降 / 缺费用数据四种情形。

## 5. 留给决策人

1. 诊断候选的一轮试跑（复用基线臂，估算约 1.3 USD）是否现在跑。
2. 若小模型在大部分问题上质量不降，这是费用和时延上最大的一笔收益；若只在部分切片上不行，再提窄路由。无论哪种，判定模型不动。

## 6. §9 自审

- 没有把路由算作 M5-04 的 token 手段；档位与阈值在测量前写定。
- 如实写了设想方案（只路由 label_query）覆盖面只有 14% 这一发现。
