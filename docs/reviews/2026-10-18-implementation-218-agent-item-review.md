## 2. 设计和实际改动

### 2.1 严格逐项材料判定

`agent_final_gate.py`把最终策略从私有v1升级为`pv-final-material-v2+item-and-evidence-groups`。真实请求带叙述、要求、草稿及**每个实际使用证据句柄的原文和引用**。旧实现最终模型未看到证据全文，只给三个总布尔值，无法可靠表达“某条要求没完整覆盖”或“这两个片段共同需要”。

新增封闭DTO：逐要求complete、逐陈述verdict/support_groups，严格真布尔、索引/UUID/数量/额外字段限制；要求集合、陈述索引必须恰好匹配原任务/草稿。支持组内AND、组间OR，不能借用其他陈述句柄，不能用空/重复组或未支持判定却给支持组。原引用核验仍先执行，新语义判断不能把原失败变为成功。JSON重复键/截断/旧三字段回复失败关闭。

结构层允许同一要求含多条事实/陈述，允许明示可选缺项，继续拒绝未知ID、错误类型、假原文和覆盖/缺失冲突。实质完整性不由ID出现与否决定；必需项任一语义不完整都否决。

### 2.2 材料编译与失败映射

新增`agent_review.py`，只接受可信Driver实际调用结果；重新绑定context/action/draft/policy/receipt及原逐条引用输入，重算派生完整性和引用结论。`PreparedReview`记录要求状态、四类门、经过核验的叙述/指南、完整支持组、真实原文/源哈希/Citation及回执。保留既有免责声明。

未经支持陈述被剔除，原草稿仍在受限执行审计。叙述整体失败不复制叙述事实；范围或本地医学建议检查失败不复制正文。结构已缺必需项时不调用最终模型，`not_run`明确区别于语义通过或语义失败。不能拿失败返回未验证生成答案。

`completion_eligible`仅为内部候选资格；run仍running、terminal仍None，没有将内部finish申请冒称业务completed。完整终态原子发布、澄清/升级业务材料为下一切片。

### 2.3 同事务、回执、恢复

`PgAgentDriver.verify_final`在原AgentFactScope最终栅栏事务内编译、追加加密审核事件并更新head，确认commit后才设置缓存/向内部调用者返回。`AgentExecution.review()`复用这条路径。

再次调用及恢复优先复用唯一已认证材料事件；验证原动作/草稿/策略/当前真实证据和持久final调用回执。读取前后仍查当前权限、来源、版本、取消与持有权。没有已提交完整材料的已知回复不能重做最终模型；有在途/未知费用不清零。原8步/12k/0.60/125秒及原引用重试上界保持。

原最终模型调用前追加当前内容比对：逐调用检查实际引用仍与注册表一致，防止引用模型之后、材料模型之前的事实漂移。该加强只在新完整最终配置路径生效，原无final_config引用预算路径的既有失败语义保留。

提交确认不确定时当前Driver进入失败状态；退出不再用旧head覆盖数据库，后续只能从持久事件恢复。材料事实已提交则可复用；没提交则停止并保留原费用，不能多调一次模型补救。

### 2.4 预算和兼容边界

新提示/Schema/实际证据进入真实startup_reserve及模型准入。最初较冗长提示在试算中进一步压缩，但没有删除数字、单位、否定、条件、未知、数据注入、共同必需/可替代及逐项要求约束。超原12k或真实字节边界的配置失败，不缩减必需证据或提高额度。

## 3. 实测失败、原因与修复

1. 逐调用事实加强最初也应用于旧无final_config路径，一条原内容漂移测试提前获得`AgentToolFault`，而其契约期待预算异常与not_started回执。限定于新v2路径；原定向29条复测通过。
2. 首次mypy报9项：version常量被推为str，混合事实/陈述tuple被推为AgentModel，以及复用循环变量导致类型冲突。常量标Final、按具体类型分集合、重命名循环变量；5个变更源码mypy通过。
3. 新测试最初把字符串写进enum的model_copy，产生Pydantic serializer warning；修为真实Verdict枚举，定向70条无warning通过。
4. 首轮PG：31 passed、6 failed，88.23秒。5项是**测试实现错误**，误查不存在的`agent_runtime_calls`：`psycopg.errors.UndefinedTable: relation "agent_runtime_calls" does not exist`。实际调用位于加密`agent_runtime_events`准入/结算事件，改查实际call_settled事件。
5. 另1项是**实际提交确认丢失缺陷**：材料已commit而确认抛错，内存head未推进，退出尝试旧revision触发`AgentLoopAbort: unsupported_recovery`。新增共同review失败边界，失败实例不再推进旧head，恢复读取已认证原材料；未提交与已提交确认丢失都测试，不以重复调用恢复。

本节保留原失败，不把第一次失败写成成功。最终修复复测和全量结果在§4登记。
