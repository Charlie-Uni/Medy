# 记录 139：正式评测的真实索引预检

日期：2026-10-08。阶段 2 / OPT-15，兼顾阶段 1 运行证据可信性。本轮自审通过；阶段整体仍待部署及外部评测证据。

## 缺口与修改

此前正式工具只检查 active chunk 是否有词法/向量行。空库、无 chunk 的 active 文档、错误索引元数据可能通过；容量脚本在没有管理 DSN 时还会跳过整个预检。

本轮复用记录 137 的真实检查，通过 `require_retrieval_integrity` 在不健康时拒绝测量。主集在本地模型加载前执行；共用 Plane 的安全/回放/recall 工具在第一条生成调用前执行。容量预检的连接成为必填，focus 诊断也使用完整检查。已知请求连接和管理员检查连接必须匹配实际数据库身份。

检查通过只说明当时 production A2/向量索引符合要求。第三方词法候选还需该候选自己的覆盖和版本证明；没有把 A2 的检查冒充 BM25 检查。

## 可追溯与失败行为

- 主集、安全集、回放、recall 和容量工具在测量前保存 `retrieval-preflight-v1` 快照，含时间、实际健康摘要和范围说明。文件名及引用有 SHA-256；续跑追加，保留早先检查。
- 失败/未知/空平面集合不能保存成功快照；写文件失败会阻止测量。主集、安全集、容量汇总带快照引用。
- Plane 在预检失败或第二个连接失败时关闭已打开的连接。只读检查使用 REPEATABLE READ、连接与语句超时；随后回滚检查事务，恢复后续原 READ COMMITTED 查询行为。
- outbox 积压保留在快照中，仍按记录 137/138 的语义与就绪分开。

## 验证结果

- 21 项针对性检查通过；本轮新增 8 项，既有真实缺索引/空词法/版本错/空文档测试同时验证正式预检会抛错。
- `env -u DEBUG make check`：**1509 passed、70 skipped、1 warning，37.67 秒**。180 个源文件类型检查、格式、评测输入和 Schema 均通过；跳过与警告原因同前。
- 实际主集 CLI 指向旧 `medops` 库，退出 1，错误原文：`IndexCoverageError: medops: retrieval preflight failed: embedding_coverage_gap, embedding_version_missing_or_mismatched`。没有进入模型加载，没有产生 rows 或模型调用。
- 实际容量 CLI 缺少指定管理变量，退出 1，错误原文：`MEDY_MISSING_PREFLIGHT_DSN is required for the retrieval preflight; no API process started`。未读取随后的 issuer 文件，未启动 API。
- 两个正式语料库在记录 138 恢复后通过严格只读预检，请求/管理连接的实际身份一致。

## 剩余限制

这是时间点上的 active 语料预检，不是整个评测期间的数据库冻结，也不证明全部归档历史覆盖或向量语义正确。容量工具检查操作者给定的管理 DSN，不能从公共 `/readyz` 验证任意外部 API 的目标库身份；启动配置仍须一致。下一轮补主集/安全集续跑时的代码、日期、模型/策略、映射与语料条件绑定，避免各次运行条件不同而拼成一个成绩。
