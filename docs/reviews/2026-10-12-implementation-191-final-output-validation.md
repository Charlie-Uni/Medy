## 2. 改了什么

1. **共享终检。** 当前目录身份须与执行时 UserContext 一致；Ask/MCP Bearer 再验签名、有效期和目录。原 QueryContext 下重读所有支持证据，比较完整 Citation、文本/哈希、状态及 historical，同时沿用来源、parse、窗口和 span 规则。
2. **保护检查至提交。** 0026 在六张身份/事实表增加 statement 写触发器；最终输出持共享事务锁，普通事实写入持排他事务锁。只在推理结束后取锁，直到审计及结果提交或回滚；读者没有新增事实写权限，旧快照模式拒绝。MCP 双 DSN 必须同库，栅栏跨只读连接关闭和 app 审计提交保持。
3. **完整支持集合。** 五类 Skill 的内层支持证据全部进入终检；最终报告未引用的块也不能省略。另捕获 evidence/doc_type lookup 的实际正负观察：引用原本不可见、期间变为可见时，旧“未知引用”结论同样不能完成或重取。
4. **已存结果绑定。** Task.completed 同事务保存私有 OutputBinding，只有身份、日期、Citation、哈希、状态与查询类型元数据；GET、幂等 POST 和 retry 返回已存结果前复核。公开 DTO/Schema 不增加此字段。
5. **期限及失败审计。** 终检/成功报告限定5秒，仍受外层剩余时间约束；锁等待1秒，不重跑模型。失败终检用 savepoint 回滚；MCP 错误和 Ask 升级保留调用统计。模拟非零已知费用/Token 的失败审计通过，实际托管费用为0。
6. **首次 SQL 原子性。** 扩展真实数据库测试发现 DeadlineConnection 第一个逐语句 transaction() 在隐式事务尚未开始时变成顶层事务，提前提交 Task.complete，审计失败无法回滚。先 BEGIN 再用 savepoint，真实首次写入回滚和既有 Task 审计故障回归通过。
7. **就绪检查。** 缺少输出栅栏函数、六个已启用写触发器或 tasks.output_binding 列时，不报告 ready。没有引入 Pool 或拆分请求事务。

最终授权点是成功提交；之后发生的撤权无法撤回已提交、可能正在网络传输的数据，后续读取再次复核。原始 PDF 不在每次输出时重下载，数据库 verified 状态的维护仍由已有来源流程负责。
