# 记录 157：回放运行绑定与事实漂移检测

日期：2026-10-09。状态：**EVAL-14 工程范围完成；未调用模型，未产生新的质量或门禁成绩。**

## 1. 目标与原问题

记录 140 已让主集和安全集运行绑定代码、依赖、样本、策略及开始时的事实摘要，但留下两个明确缺口：

1. 回放的 baseline/candidate 两臂没有逐行绑定各自实际运行的 `VersionSet`，恢复运行时可能把旧行与新配置合并；
2. 事实摘要只在开始时生成，长时间运行期间语料、ACL、文档状态、chunk 或索引语义元数据变化不会使结果失效。

此外，旧 `--baseline-from` 只比较 replay dataset hash、subset 与 baseline version。它没有核实实际代码、Python/依赖、完整样本内容、事实库、策略 diff、作答提示和评分口径，也不保存被复制尝试的原始身份。这不足以证明两个运行的 baseline 真正相同。

本轮不调整冻结数据、gold、评分规则、正式门槛、模型路由或发布策略。`source-constraint-v1` 仍默认关闭。没有运行付费样本。

## 2. 实现

### 2.1 回放两臂绑定实际执行条件

`replay_run.py` 现在在第一条模型调用前写入 `run_conditions.json`，内容包括：

- 当前源码、runner、schema、lockfile 和关键资源的 SHA-256；
- Python、平台及关键依赖版本；
- replay 主样本和安全样本的完整输入哈希与固定顺序；
- baseline/candidate 各自实际 `VersionSet`；
- 两臂完整策略摘要、混合检索参数、rerank 输出、glossary、多查询、文档聚焦、来源约束、翻译、上下文聚焦、模型路由和作答提示哈希；
- 主库与安全库的数据库身份及事实摘要；
- 日期、设备、GPU 超时、运行轮数、subset、安全开关、gate seed、月度预算、dataset/scoring/candidate 文件哈希。

每个主集和安全集尝试逐行保存唯一 `attempt_id`、条件哈希、样本哈希和**本臂**版本。恢复前检查完整历史。条件变化、旧行无绑定、样本/版本错臂或损坏费用字段都会拒绝在原目录续跑。

`--max-cost-usd` 是本次进程的停止上限，可以在获得新授权后提高，因此不进入科学运行身份；实际费用仍逐行落盘并由数据库费用账本约束。轮数、样本计划和会影响结果的配置仍属于绑定条件。

### 2.2 合法重试与费用口径

同一 `(arm, run, replay_id)` 只有在前一条为 `system_failure` 时才允许追加新尝试。第一次失败不会被删除；成功行之后再次重复会被拒绝。报告新增：

- `attempt_accounting`：目录内所有尝试，包括失败重试和带来源证明的复用尝试；
- `recorded_attempt_cost_usd`：上述全部已记录尝试的历史费用；
- `retained_outcome_cost_usd`：各题最终保留结果的费用；
- `current_execution_cost_usd`：本次进程新产生的费用；
- 兼容字段 `total_cost_usd` 保持“本次进程费用”口径，并用 `total_cost_scope` 明示。

进程在模型响应后先写行、刷新文件，再判断 GPU stalled、连续系统失败或费用上限，避免退出时丢失已产生的费用。

### 2.3 基线复用

新的 baseline reuse identity 只排除候选臂内容、轮数和 gate 随机种子；它要求下列 baseline 条件完全一致：

- 源码和运行环境；
- 完整样本计划与 dataset/scoring；
- 两个事实库及事实摘要；
- baseline 实际版本、策略摘要、提示和检索设置；
- 日期、设备、超时及其他会影响 baseline 的运行配置。

复用前还要求来源运行：

- 有完整、未篡改且与 `results.json` 相互绑定的运行条件；
- 评分版本一致；
- 请求轮数内每个 baseline 样本都有最终行；
- 没有尚未恢复的 `system_failure`；
- 每行样本、版本、费用和模型调用字段均通过校验。

复制时保留所有失败后重试历史，并写 `source_attempt_id`、`source_run_conditions_sha256` 和 `reused_from`；新行同时绑定当前运行条件。候选内容可以改变而不使真实相同的 baseline 失效。旧的无绑定历史运行不能再作为新实验的基线来源。

### 2.4 运行中事实漂移

新增通用 `FactGuard`，用于主集、安全集和回放：

1. 开始前强制重算事实摘要；
2. 运行时默认每 300 秒、在下一题开始前重算；
3. 正常生成报告前强制重算；
4. GPU stalled、连续系统失败或费用停止前也强制重算。

任何目标库摘要变化都会抛出 `FactDriftError`，明确要求丢弃这次测量并使用新目录。重新启动时，新的开始快照也无法与旧 `run_conditions.json` 合并。

每次重算使用独立的管理连接和只读 `REPEATABLE READ` 事务。正式运行器现在从 `Settings.database_admin_url` 派生主库和安全库 DSN；缺少管理 DSN 会在模型加载/调用前退出，不会静默回退到可能不同的 `.env` 连接。

事实摘要覆盖 source object、文档状态/版本/有效期、chunk 正文、页锚点、ACL、词法及向量索引语义元数据；只保存行数和哈希，不输出正文。

## 3. 自审中发现并修复的问题

| 发现 | 原因 | 修复与验证 |
| --- | --- | --- |
| 最初把相同 `(arm, run, replay_id)` 一律判为重复 | 忽略了既有 resume 设计会保留 `system_failure` 后追加成功尝试 | 改为只允许系统故障后的顺序重试；成功后重复仍拒绝；增加失败费用保留测试 |
| 最初基线复制只复制同一 key 的第一行 | 对带失败重试的历史会复制失败行、丢掉最终成功及部分费用 | 按 key 选择是否整体复用，再按原顺序复制该 key 的全部尝试；要求最终行无未解决系统故障 |
| baseline identity 初稿仍包含 candidate policy snapshot | 虽然排除了 candidate version/file，候选策略摘要仍会使基线身份变化 | 分离 baseline/candidate 策略摘要；候选单独变化允许复用，baseline/代码/事实变化拒绝 |
| `max_cost_usd` 初稿进入绑定条件 | 新授权提高停止上限后无法恢复同一实验，尽管实验行为未改变 | 从科学条件中移除，费用和调用仍由尝试行、数据库账本及本次执行字段审计 |
| 受控提前退出留下最后一个未检查窗口 | 周期未到时，最后一次调用期间的事实变化可能在退出前漏检 | GPU stalled、连续故障和费用上限路径均增加强制检查 |
| safety/replay 的管理 DSN 可从 `.env` 辅助函数读取 | 进程环境覆盖与 `.env` 不一致时，应用连接和事实检查可能落到不同服务器 | 明确使用已校验的 `Settings.database_admin_url` 为各库构造 DSN；缺失即调用前失败 |
| 定向 mypy 首次报告 6 个错误 | 新集合缺类型、`Any` 未缩窄、`Settings()` 的环境注入类型提示、变量 `r` 同时代表 `HarnessRun` 和报告行 | 分别补类型缩窄、既有 `type: ignore[call-arg]` 约定并改名 `ask_run`；复跑 mypy 通过 |

mypy 原始摘要为：`Need type annotation for "attempts"`、`Unsupported operand types for > ("int" and "None")`、`Missing named argument "database_url"/"redis_url" for Settings`，以及 `HarnessRun` 与字典行变量冲突导致的两条类型错误。它们均在全量检查前修复。

## 4. 验证

### 4.1 自动测试

定向检查覆盖：

- 条件不变可恢复，源码/依赖/样本/事实/配置/版本变化会拒绝；
- 两臂行必须绑定本臂版本；
- 失败后重试允许且费用累计，成功后重复拒绝；
- 基线只复制请求轮数内的 baseline，candidate 单独变化允许，baseline 执行身份变化拒绝；
- 缺失/损坏条件、结果绑定、评分、样本行或未解决系统故障全部在复制前拒绝；
- 周期检查、强制终检和事实变化报错；
- 主集与安全集 runner 的恢复及退出控制流。

## 5. 限制与后续

- 这是检测并作废，不是把数据库锁住。两个 300 秒检查之间发生又恢复的瞬时变化理论上不可见；硬杀进程也无法执行退出终检。
- 每轮双库检查当前约增加 2.5 秒，每五分钟一次。正式运行应保留这个默认值，若语料规模显著增长再评估增量摘要或变更序列号，不能直接取消保护。
- 摘要不逐字节重哈希 pgvector 向量；索引构建完整性仍由 preflight/metadata 负责。远程模型名称相同也不能证明供应商权重永久不变。
- 旧回放没有本轮要求的条件和逐行身份，只能保留为历史报告，不能用 `--baseline-from` 混入新正式门禁。
- 本轮没有调用模型，因此没有证明主集、安全集、来源候选或其他策略的答案质量提高，也没有重计验收门槛。
