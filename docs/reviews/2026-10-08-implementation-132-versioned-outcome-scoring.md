# 记录 132 无答案评分修复与评分版本隔离

日期：2026-10-08，Australia/Sydney。阶段 1、OPT-12。等待具体人工意见期间，继续完成不依赖该意见的工程工作。本轮范围为主集行为评分、运行绑定和回放导出；不宣布完成语义支持/答案完整性评分或阶段验收。

## 1. 问题与依据

旧 `replay_run.main_success` 对 no_answer 仅检查 `outcome != "answered"`；`build_replay_set.label_main` 同样会把系统故障升级标 good。它们没有区分“系统正常执行后发现证据不足”和“根本执行失败”。主集运行器虽然检查 insufficient_evidence，却未排除同时带 system_failure 的异常组合。

依据评测标准，无答案样本应按其预期处理，系统故障和超时必须单列，仍留在质量分母。现行 main-v1/v2/v3 各有 61 条 no_answer，expected_behaviour 均为 insufficient_evidence；这使旧 replay 未导出预期字段时的兼容解释有可检查依据。

## 2. 修改

新增共享 [main_scoring.py](../../src/medops/evals/main_scoring.py)，评分版本 `main-outcome-v2`：

| 情况 | 新规则 |
| --- | --- |
| 无答案正常证据不足 | outcome=escalated 且原因码集合恰为 insufficient_evidence，成功 |
| 系统失败、超时、缺少原因、其他安全升级、无答案却作答 | 失败，不从分母删除 |
| 有答案/冲突 | answered、无升级原因、gold 覆盖符合该数据版本；显式组 AND/OR，旧扁平 gold 保留 any-hit |
| 未支持的 kind 或未来 `refuse` 期望 | 模型加载前拒绝，须先明确并校准评分规则 |

接入主集 `smoke_ask.py` 与 `replay_run.py`：

- 每个新运行生成 `scoring_binding.json`，每行记录 `scoring_version`，汇总/回放 gate 保存评分说明。
- 续跑拒绝缺绑定、不同绑定和混合版本行；`--baseline-from` 要求来源评分完全一致，先检查全部源行再复制。该检查已移到模型加载之前，避免先加载模型才发现结果无法复用。
- 主集新行保存 expected_behaviour 与 success；新 replay 导出携带预期和评分版本，按新规则标签。旧无版本数据保留原标签解释，未覆盖已有冻结目录。
- 汇总新增弃答诊断：正确证据不足弃答、证据不足型误弃答（有答案分母包含冲突题）、系统失败及无答案其他失败；提供分子、分母、比率，空分母为 null。原摘要的普通 answerable 字段继续有其较窄分母，新字段明确命名，避免混读。
- 新版有答案成功仍是行为和 gold 覆盖代理指标；它不能证明逐句语义支持或内容完整性。评分绑定明确写出未测项。
