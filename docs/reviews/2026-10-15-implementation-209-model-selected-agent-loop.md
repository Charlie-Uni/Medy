## 1. 实施与范围

AgentLoop通过实际ModelRequest/MeteredGateway每步请求一个动作，严格沿用PlannerProposal/admit_action，使用原四工具/Registry。工具事务由必需Driver保存、提交后返回，再核验绑定/原文/句柄/来源/回执集合并构建下一请求。生产代码不读取S0编号或评测期望，不按规则替模型选下一业务动作。假网关读取实际观察后选择空检索改写、邻块读取、核验、澄清等不同路径，验证动态接线。

每步开始同步checkpoint消费步数；非法/截断/失败及terminal申请都计数，无免费格式修复或第九次请求；规划与AE共享一个根预算，失败/未知usage及保守费用保留。继承根guard并在物理规划调用前重新核验当前身份/证据。出错日志保留类型和最内层帧位置，不记消息。

规划者只看有界用户数据投影，最多64句柄元数据/最近8份正文、32项claim检查；保留原数字/否定/条件，旧正文显式omitted且仍可read，长read不被短搜索覆盖。失败payload不进入知识状态。原完整Pydantic schema 6115字节；公开合成首请求预检无schema3780、有完整schema9895单位，差6115，并非真实供应商Token。当前用紧凑JSON说明加本地闭合验证，不修改原Skill structured-output配置。真实Prompt SHA为实际SYSTEM内容摘要，显式模型/输出/时间配置无新默认。

仅内部循环，不提供默认/生产Driver、HTTP/MCP入口、实际恢复、完整最终门或SESSION。finish只是terminal_request，run保持running/terminal=None，不能算业务完成。规划调用保护最终预留；全工具最坏消耗分配/无进展/持久取消与租约仍AGENT-04，最终门AGENT-05，完整持久化AGENT-06。没有把Driver接口说明当已实现数据库行为。

相关去重复：AgentTools原私有微USD转换与新控制器共用core.money，函数体完全相同；原工具其他方法仅函数名引用改为共用函数，另做AST比较。没有改价目表、舍入、预算上限、默认模型或工具契约内容。

## 2. 错误、困难与补救

1. 初次静态发现Driver异常边界BLE001及import排序；以固定audit_failure和不带消息的类型/位置日志处理存储异常，显式说明边界，ruff/类型复测。
2. 初始定向30 passed/2 failed：handoff测试预期1次调用，实际search后finish为2次合法决策；未准入模型测试试图匹配被既有隐私规则隐藏的错误detail。修测试为2次及ModelUnavailable类型，不放开原错误正文。
3. 扩展为40 passed/1 failed：Fake网关误禁止原AE Skill在工具事务中调用模型，导致真实Registry返回dependency_error。只要求下一规划不在前一工具事务内；保留原工具事务政策，修fake断言只检查agent_plan。没有为测试拆掉旧事务/安全门。
4. 逐段自审发现“schema有效”不足以证明来自本动作/合法句柄：加入信封/动作/原文前缀/truncated/来源/实际回执集合和逐claim对应关系校验，错误归audit_failure；ok空结果、empty非空结果、额外未展示句柄等反例均拒绝。根异常原先只有固定停止原因，补异常类型/最内层帧日志，验证不带私有消息。
5. 首轮全量2880 passed/70 skipped/1既有warning通过后，继续范围自审发现工具内容契约要到执行工具时才验证，可能先付一次规划费。把比对提前到首次规划前，新增零调用反例，补版本检查后的2881/70/1仍通过；之后预算拒绝分支再修复，最终2883/70/1，不以较早快照通过替代最终快照。
6. 只读定位时误用几个旧/猜测路径，rg提示No such file；改用rg --files确认infrastructure/llm和现有nodes.py。失败搜索未修改仓库。原失败日志均保留，不伪造独立审核。

7. 最后费用路径自审发现handoff在“尚未绑定新执行预算”时直接读取当前父scope：拒绝旧运行会把原17 Token/1,200微USD清零，拒绝其他已消费父额度会把它抄入新run。新增反例先复现2 failed/6 passed/42 deselected；修为只有全新run及零消费父额度校验通过后才绑定预算，快照只同步这个绑定，拒绝分支保留输入原费用/预留，并在每次调用前拒绝替换scope。两条复测及最终273定向/2883全量通过。没有写费用账本或释放任何旧预留。
