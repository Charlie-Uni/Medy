## 1. 冒烟 v1（20 条：每部门 5 条有答案、3 条无答案、2 条冲突）

- 有答案 15/15 回答，且全部引用了样本的 gold chunk；冲突 2/2 引用现行版；费用 0.13 美元，平均延迟 7.1 秒。
- **无答案 3/3 被"回答"**。复看内容：模型写的是"所提供的证据未载明逾期通报的罚款金额"这类说明性陈述，判定模型判其有依据（确实有依据），链路把它当成了答案。这是 Answer 节点缺少"证据不回答问题"这一出口，不是幻觉。
- 修正（提交 `7490d25`）：(1) 输出 schema 增加 `answers_question`，提示要求证据不回答时置 false、claims 为空、不写说明性陈述；(2) 不依赖模型自述的兜底——全部陈述都命中"未提及/未载明/not specified/cannot be determined"类模式即按 `insufficient_evidence` 升级。两者都有单元测试。

## 2. 冒烟 v2（78 条：全部 61 条无答案 + 15 条有答案 + 2 条冲突）

| 有答案样本误弃答 | 0 / 15 |

- 唯一未弃答的 ms-0462：问题以"根据 GVP Annex I"限定，Annex I 确实没有 ICSR 时限，但语料中 GVP Module VI 有（15 天），检索把 Module VI 的条款召回，模型据此作答并引用 Module VI。这是 spec-m1 无答案样本"按文档限定范围"与系统"按语料回答"之间的口径差（记录 53 对 ms-0499 已指出同类问题），不是链路缺陷；升版 `main-v1` 时应把这类样本的期望行为改为"回答并引用正确文档"或改题。
- 对照记录 51 的近似口径：用重排分数阈值近似弃答只有 21.3%；M2 路径把弃答交给 Answer 的判断加规则兜底后为 98.4%。spec-m1 §6 写明阈值口径待 M2 Verifier 决定，本节即该口径的首个实测。
