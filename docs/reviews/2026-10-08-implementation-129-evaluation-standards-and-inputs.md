## 2. 为什么要做这些改动

### 2.1 冻结状态不等于完整的运行输入保护

三个运行器此前会读取 manifest，但缺少统一的冻结文件哈希验证和数据版本续跑绑定。一个目录声明 frozen，不能证明运行时文件仍与清单一致；仅按 sample_id 跳过已跑题也不能证明属于同一版本。新增共享 `medops.evals.datasets`，复用现有三种 manifest 格式，校验文件和复核附件，避免先装模型或开始付费才发现数据损坏。

审计清单额外固定 manifest 哈希，检查其元数据没有偏移。运行目录绑定 dataset id/version/hash；它目前不代替模型、策略、语料、索引、评分等全部实验条件的绑定，正式实验仍须逐项记录。

### 2.2 原裁决已有，但没有进入新版主集

原优先表已有决定，不能继续说 0/32，也不能重复请求已给出的同意。原表 32 行实际是 28 题；其中需要版本化处理的 13 题，当前 main-v3-provisional 仍是原标注。

多块争议中的 rp-0121 对应 ms-0124、rp-0200 对应 ms-0205、rp-0238 对应 ms-0243，分别要求 4、4、2 组共同证据。本轮整理了历史 chunk 依据并实现组计分，但尚未为这些题生成新的多锚点 gold、映射或冻结版本。不能直接把全部相邻 chunk 扔进一个 OR 列表后声称修好了标注。

### 2.3 版本关系和统计口径需要显式记录

- probe v2 为 107 题；它们已包含在主集，不能累计为额外独立题。
- main v3 为 614 题：553 有答案、61 无答案，52 冲突题包含在有答案题内。200 题为派生题；v1–v3 的样本字节相同，语料快照不同。
- 主集映射 546 mapped、7 unmappable。未映射项留在 553 分母中，按未命中计算。
- safety v2 已冻结 170 题、撤下 7 题。当前草案内容与冻结样本逐项相等，故本次草案 DB 检查可用来描述这 170 条样本的当前机械检查结果。
- replay v3 为 614 主集项、170 安全项，筛选 200；安全来源仍是 v1 草案，其中 7 个编号已退出安全 v2。冻结旧回放可以复现历史输入，不能用它替代新安全版本成绩。
- 主集来源语言和 query 语言是不同分组维度。按五类必复核风险标签的并集是 492 题，另有 122 题；还需并入其他争议再对余项抽样。

## 3. 对现有代码和使用方式的影响

记录 126、127 的去重和职责拆分继续适用，记录 128 的启动与接口检查保留。本轮未修改 API 业务、已发布策略、默认模型、ACL、正式验收阈值或冻结文件。

评测入口有以下有意改变：

1. 文件哈希不符、manifest 声明不符会在模型装载前报错。
2. 有 `rows.jsonl`、没有数据绑定的旧运行目录不能直接续写，需使用新的运行目录。原始行和结果保留。
3. 有绑定的运行必须使用相同 dataset id/version/hash；安全运行不能在省略 `--dataset` 时退回草案继续写。
4. `safety_run --rejudge` 不能原地覆盖冻结数据运行。旧草案诊断路径保留；新诊断应另存，不重写正式历史成绩。
5. `smoke_ask --ids` 现在从显式指定的数据集取题，修正了该分支之前会退回默认主集的问题。
6. 新运行输出证据组与 `gold-groups-v1`。当前有答案题都是单组；未来新版多组题将要求完整覆盖。旧回放没有组字段时仍用旧规则。

这类报错是输入保护，不是正常问答功能退化。配置和文件正确的新运行可按原 CLI 参数执行。
