# 记录 136：逐句引用快照与语义/完整性诊断

日期：2026-10-08。阶段 1 / OPT-12。本轮工具自审通过；真实裁判校准与语义成绩尚未完成。

## 为什么补这一层

工程基线 §5.9 的引用准确率要求原文支持引用。现有 gold 覆盖与引用结构检查有各自用途；旧主集行仅保存句子列表和引用总列表，不能可靠还原每句话究竟用了哪些引用。后续即便重新从数据库取文本，也不能证明是当时的原文或逐句对应关系。

## 实际修改

1. 新主集运行保存 `answer-review-input-v1`：最终 Answer 的逐句引用、当时已授权 Evidence、文档标题/版本/source_hash、query、gold 单元、样本哈希和运行版本。正文文件按内容哈希命名，留在 Git 忽略的 `answer_review_inputs/`；运行行保存引用和哈希。
2. 文档身份只通过当前提问者的 RLS 连接读取，不借管理员权限补全受限文档。原页内容哈希、引用对象和对应文档版本不一致时不接受快照。
3. 保存补充材料失败时仍保存已完成回答及其费用行，明确标 `answer_review_error`；错误只输出类型，避免把 DSN/SQL/正文带入错误字段。后续语义报告会拒绝缺材料的运行。
4. 新[诊断 rubric](../../evals/answer_quality/RUBRIC.md)分别定义 claim 支持、引用支持和回答完整性。输入不给出旧 Verifier 判词；联合证据、数字/单位/否定、指定来源、漏答分别说明。
5. 新离线 `evals/harness/tools/answer_review.py` 校验实际意见和快照，汇总三项指标与分母。缺意见/无法判定时 rate=null；零分母也是 null。有答案弃答计 incomplete，无答案题不进入完整性分母。重复 case 意见须显式裁决，不能最后一条覆盖。
6. 模型意见须记录实际模型和提示哈希，且必须声明不是第二人工。格式校验只能核对记录的一致性，不能证明模型真的执行过；实际执行证据仍要保存。

原 `main-outcome-v2` 与业务门槛保持。新报告固定 `formal_gate=false`，独立校准前只作诊断。没有为旧运行反向补造快照、没有付费模型调用、没有新语义成绩。

## 发现与修复

- 首次 mypy 报 `Incompatible types in assignment (expression has type "dict[Any, Any] | None", variable has type "dict[Any, Any]")`，是同名循环变量承接可选查询结果；已改为独立变量。
- 自审发现若补充快照写入失败后直接抛错，会丢失已完成的付费回答行；已改为显式记录材料缺失，保留运行结果和费用，语义报告则拒绝缺材料。
- 单看 doc_id 无法审指定文件，补充当前权限下的标题、source_hash、document_key 和版本，并新增真实 RLS 集成测试。
- 主集行与快照还额外核对 query、部门、句子、引用、终态、版本和样本身份，防止把另一份输出的意见套用过来。
