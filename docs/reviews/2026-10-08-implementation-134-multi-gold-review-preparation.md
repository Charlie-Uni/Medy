## 目标与实现

用户已确认 19 条修订并说明暂时只有本人和模型。本轮把确认后的材料整理成可运行、可追溯的独立模型复核包，不代填第二人工。

- 新增 `multi-gold-review-v1`：每个 gold 单元保留来源、版本、页、key 和 span，同页全文去重。打包和 provenance 重建共享同一实现；缺第二页会报缺失，不能退化成只审第一个 gold。
- 旧单 gold 记录格式和历史提示保持原样。主集新提示明确联合证据、来源要求和跨页 long_context；探针三题沿用探针提示。
- `prepare_revision_review.py` 在写输入前校验修订、页锚点、第一人工确认文件及其逐题哈希，应用已批准的 FDA 标题修正。
- `run_review.py` 支持独立复核目录和提示文件；`draft_common.py` 支持向 CLI 传单次费用参数。该参数不代表整批预算，失败和重试仍需单独入账。
- `eval-check` 现在验证确认事件与目录文件/19 条标注/39 个 gold 单元之间的绑定；不能把修改后的材料套用旧确认。
- 四个本轮维护的主集工具加入 Makefile 的 lint/format 范围。

[复核包](../../evals/main_set/drafts/revision-2026-10-08-v2/review/README.md)分主集 CO 3、EN 6、PV 7 和探针 MA 3；合计 19 题、39 个 gold 单元，其中 10 题采用多证据协议。全文输入留在本地并由 Git 忽略。实际调用数为 0，费用为 0；已询问本次付费复核预算，等待回复。

## 自审发现与修复

1. 旧工具硬性要求一个 gold，不能承载本次相邻块/跨页修订。已扩展打包与重建两端，补缺页、重复 gold、错误 span、重复 key、版本错配、缺孪生父题的失败路径。
2. 初版提示仍有旧的“span 超 1500 字符”表述，容易误判跨页题；现已统一为任一 span 超阈值或至少跨两页，且不要求不同页证据必须连成一个 span。
3. 新增回归题有起草备注，可能影响独立判断；多证据输入移除 notes，不发送第一人工批准和旧意见。旧单证据协议为历史复现保留原样；本包其他条目无此备注。
4. 初版准备清单写 `prepared_not_executed`，重复准备可能让已执行状态看似退回；改为只表述准备事实 `inputs_prepared`、`model_calls_by_preparation=0`，执行记录另存。
5. 第一轮新测试把格式名里的 `review` 误判成泄漏字段（`assert "review" not in json.dumps(record)`）；改为检查 JSON 字段。mypy 报 `Unused "type: ignore" comment [unused-ignore]`，删除无用忽略后复测。
6. 直接 `make check` 出现 7 failed、1185 passed、297 skipped，错误均为 Settings `debug` 的 `Input should be a valid boolean, unable to interpret input`。外部 shell 的 DEBUG 值不适用于本应用，亦令集成 fixture 无法加载设置。沿用记录 132 的 `env -u DEBUG make check` 后全部通过；没有放松 Settings 验证。运行命令的环境隔离仍需维护者注意。
