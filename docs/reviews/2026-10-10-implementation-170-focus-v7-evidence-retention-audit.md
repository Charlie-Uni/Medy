# 实现记录 170：v7 上下文裁剪的证据保留审查

日期：2026-10-10。对应 FOCUS-01 / M5-04。本轮为本地诊断，不是正式回放门禁，也不是第二人工复核。API 调用与费用均为 0。

## 1. 为什么继续检查

[记录 119](2026-10-05-implementation-119-sentfocus-v7-pilot.md)的旧离线结果为 494/496 个 gold key 保留（99.6%），旧试跑实测 Token −27.2%，但 CO 切片退化、规则行误弃答和运行只有一轮，未通过门禁。[记录 120](2026-10-05-implementation-120-sentfocus-v8-pilot-and-choice.md)建议保留 v7 进入后续正式评估，同时明确不再连续生成 v9、v10。

99.6% 的分母仅包括当时已经出现在证据中、并能在单块完整定位的 key。旧工具还用“至少一个 key 保留”统计成功题有没有隐藏 gold。这不能回答当前标注规则下“多个共同必需的证据是否全部保留”。另外，key 是短答案锚点，不一定包含完整标注片段里的条件、否定或监测要求。

因此本轮检查保持原候选定义，采用新冻结主集的标注与映射，区分 key、完整标注片段以及完整证据组。没有把本轮新诊断指标偷偷写成原门禁。

## 2. v7 当前如何裁剪

1. 输入为检索、事实回查和整块重排后最多 8 个证据块。
2. 按中英文句末标点划分单位；不足 5 个估算 Token 的碎片合并；超过 240 字符的长段可在分句或空白处再次切开。
3. 第一名证据整块保留；短块（≤60 个估算 Token）及只有一个单位的块整块保留。
4. 其他单位由同一个 `bge-reranker-v2-m3` 对原问题及最丰富的改写问题评分，最多两个查询变体，取每单位最高分。
5. 每块保留最好单位及其前后各一个单位。其他单位跨块竞争，补到全文单位估算 Token 的 60%。这些保留底线可能超过 60%；它不是硬上限。
6. 按原文顺序拼接保留单位，缺口标 `[…]`；用 E1/D1 别名压缩标记。文档标题固定截到 60 字符，版本留在图例；页码从生成提示头部省略，原始 Citation 的页码仍在。
7. 图例包含点名来源缺失时输出 `answers_question=false` 的规则行。

算法并没有显式识别所有数字、否定和条件的依赖关系，也没有对共同必需证据建立闭包。前后各一单位是启发式保护；条件离得更远、长句被再次分段、关键解释位于另一块时，仍可能遗漏。

生成阶段使用裁剪文本，AgentState、安全检查及声明核验仍使用原始完整 Evidence。完整块的核验可以检查某项陈述是否被支持，却不能自动证明生成提示包含了回答问题所需的全部条件或答案已经完整。

当前 Redis 保存候选与整块重排次序；句子聚焦是在生成节点另外执行的，本轮没有句子评分缓存。若以后启用 v7，检索缓存命中仍可能需要这部分 BGE 打分。节省生成 Token 不自动等于降低总时延，这也是旧 v7 试跑 P95 17.5 秒仍高于基线 16.5 秒时需要保留的取舍。

## 4. 计分规则

| 检查 | 规则与限制 |
| --- | --- |
| gold 的映射备选 | 同一个 gold 的多个重叠映射块任选其一，OR |
| required gold 组 | 各 gold 共同必需，AND；未映射或未检索到的保留为 miss |
| key 保留 | NFKC、忽略空白和英文大小写后，在对应证据正文中仍能完整定位 |
| 完整标注片段保留 | 对映射备选单块能完整定位的 `evidence_span.text` 单独检查；跨块片段本轮不拼接，定位不足保留为缺口 |
| 省略标记 | 保留 `[…]`；不能删掉标记，再把缺口两侧拼成原来不存在的连续 key |
| 标题与标记 | 图例、标题、版本、规则行不参与证据正文的 key 命中 |
| 数字/否定/条件线索 | 仅用于给丢失片段标复核线索；正则匹配数字不等于剂量错误，片段不完整不等于答案错误 |

完整标注片段可能包含问题未要求的补充说明。因此“span 丢失”用于定位候选风险，不能直接当作医学语义错误；实际错误与答案完整性仍需固定 rubric 的答案级复核。

映射的 `mapped` 含义是单个同来源/版本/页的 chunk span 覆盖唯一 `key_text` 区间，[映射实现](../../src/medops/evals/probe/chunk_mapping.py)明确不拼接碎片；它没有承诺整个 `evidence_span.text` 都在该块里。例如 `ms-0440/0441-g4` 的 CYP P-450 key 在旧上下文末尾，具体抑制剂示例延伸到后续块。因此本报告的“完整 span 可定位”是单映射块口径；定位失败不能一概解释成标注错误，跨块全文覆盖需要另行按来源坐标检查。

### 7.1 自查发现的异常评分缺陷

原 `focus_texts` 只检查分数数量。合成注入 `NaN`、正无穷、负无穷时，三种向量都被接受，均继续保留 15/24 个单位。原因是 `max(-inf, score)` 和后续排序把异常值用于选择，却没有像整块重排的 `RankedEvidence` 一样拒绝非有限数值。

新增回归测试先在原代码运行，得到真实失败原文：

```text
Failed: DID NOT RAISE ValueError
AssertionError: assert ('answered' == 'escalated')
4 failed, 16 deselected
```

最后一项通过 fake gateway 证明不仅是纯函数接受了异常值，Harness 还会继续请求作答。该注入是合成测试，不是实际 BGE 在本轮产生了 NaN。本轮审查记录器已经拒绝此类分数，真实审查 1,035 个分数向量均正常。

固定源码审查完成后已补运行时有限性检查：异常评分直接失败并按系统故障升级，在调用作答 API 前终止。4 项回归全部由失败转为通过；614 条正常分数重放的渲染与保留结果不变。该错误边界修复不修改任何 v1–v8 候选参数。修复前渲染模块 SHA 为 `25421573…0a9a71`，修复后为 `da18b6ec…fd7936`，精确值在核验文件。

## 8. 复现

先确认同一事实摘要、输入与模型缓存，使用新的输出目录：

```bash
env -u DEBUG HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 venv/bin/python \
  scripts/audit_focus_candidate.py \
  --run evals/harness/runs/2026-10-02-full-ask-v4-released \
  --dataset evals/main_set/main-v5-provisional \
  --mapping evals/experiments/e2e/main-v5-provisional/chunk_mapping.chunker-v2.main-v5-provisional.json \
  --snapshot .local/experiments/focus-candidate-audit-reproduction/context.json \
  --out /tmp/medy-focus-v7-audit-reproduction \
  --as-of 2026-10-10 --device mps
```

本轮不报告服务 P95。评分计时包含未单独排除的首次推理，且全量检查曾同期运行；它不具备正式时延对照条件。

修复后重放脚本留在本机 `.local/experiments/focus-candidate-audit-2026-10-10/verify.py`。它核验完整输入快照哈希，用逐次 query/unit 哈希绑定的保存分数代替 BGE，再比较全部渲染与保留字段（仅计时字段排除），没有新增模型调用。完整快照与脚本均可供本机复查；独立复现评分仍使用上面的正式工具入口。

运行时出现框架警告：`The Transformer cache_dir argument is deprecated.` 模型仍从固定本地缓存正常加载。它来自现有生产构造参数，本轮没有同时更换模型加载方式、精度或 revision；属于兼容维护项，不是本次保留判定失败。
