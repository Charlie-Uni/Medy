## A. 跨语言召回

### A.1 词表成为可发布的检索参数

- `retrieval_params/hybrid` 新增键 `glossary`，值为词表版本（`glossary-none` 或 `glossary-<YYYYMMDD>-<sha12>`）；`ReleasedPolicySet.glossary_version()`，`validate_diff` 校验格式。
- 版本文件按 ADR-0008 放在 `GLOSSARY_DIR`（新配置项，`.env.example` 已加；本地与评测工具默认 `evals/glossary`）。`medops.retrieval.glossary_store.load_versioned_glossary` 在加载时核对文件声明的版本与条目摘要（sha12），任何不一致都以 `dependency_unavailable` 失败关闭；API 启动时即加载已发布的词表，缺文件启动失败。
- 词表版本进入 `retrieval_version`：`RetrievalVersionInputs` 新增 `rewrite_params`，只在有词表时参与哈希；`glossary-none` 下八成员复合哈希逐字节不变（`PRODUCTION_RETRIEVAL_VERSION` 测试与记录 90 的 baseline 版本都不受影响，`--baseline-from` 复用仍然成立）。
- 接线点：`api/runtime.build_deps` 与每请求版本、MCP `_searcher_factory`、评测平面 `safety_run.Plane(glossary=)`、回放运行器按臂解析词表、`recall_diag.py --glossary`。
- 测试：`tests/unit/retrieval/test_glossary_store.py`、`test_production.py`（词表进哈希 / none 不变）、`test_policy_loader.py`（glossary 键）。

### A.2 中英概念词表

`evals/glossary/tools/build_concepts.py`：从 46 份英文语料文档的 1,376 页页文本机械抽取 2–4 词高频短语（两端不为停用词、不含数字、tf ≥ 6 且 df ≥ 2、嵌套短语并入长短语、按 tf·log2(1+df) 取前 500），每条附出现页（document_key + page）；再用 gpt-6-sol 结构化输出逐批判断是否为术语并给出简体（大陆用法）与繁体（台湾用法）译名。回放集与主集的问题文本不进入这一步（INV-EVAL-01）。`build_glossary.py --concepts` 把 keep=true 且英文原词能在引用页上逐字找到的条目并入词表（kind `concept`，中文为 term、英文为同义词；同一中文对应的单复数 / 英美拼写合并为同义词；中文短于 3 字的不收，因为 CJK 按子串匹配）。

结果与费用：见 A.4 表。

### A.4 结果

**第二个根因**：复测第一版词表（`glossary-20260926-e5c460d55829`）时召回一题未变，追查发现 `ProductionRetrieval._retrieve` 只把改写后的第 1 条查询（规范化原句）送去检索，第 2 / 3 条（会话实体、词表同义词）只记录到 Trace、从未参与检索——M1-13 的改写器在检索里一直是死代码。修法：新增可发布的检索参数 `multi_query`（默认关，行为与哈希与今天完全一致；开启时每条改写查询各自走词法 + 向量 + RRF，再对各查询的融合名次做一次同 k 的 RRF，重排仍用用户原句），单元测试 `test_fuse_queries_*`、`test_multi_query_*`。

| 项 | 数值 |
| --- | --- |
| 概念抽取 | 46 份英文文档 / 1,376 页 → 500 个候选短语；gpt-6-sol 判定 276 个为术语，费用 0.274 美元（`evals/glossary/sources/concepts_2026-09-26.json`） |
| 词表版本 | `glossary-20260926-e4daca58a8e4`：532 条 = 概念 436（中文 term → 英文同义词，单复数已合并）+ 商品名 58 + 缩写 38；第一版 e5c460d55829 因未合并单复数作废、未发布 |
| 复测（60 bad + 30 good，`2026-09-26-recall-diag-v3-glossary-multiquery`） | 召回失败 40 → 37，gold 进前 8：18 → 20（rp-0039 繁体仿單、rp-0379 ICH E17），对照 30 题不变（前 8 全中、25 题第 1 名不变），每题时延不变（7.6 → 7.5 秒）；48/90 题产生了第 2 条查询 |
| 门禁评测 | **未跑**：+3/60 的召回增益折合子集约 +1 pp，远低于 +5 pp 门槛，不值 6.4 美元 |

**为什么词表帮不上 24 道跨语言题**：词表覆盖的是语料高频通用术语（上市许可持有人、信号检测、成员国），而这些题的关键词是中文长尾实词（安全公告、施压、参考成员国、术语粒度）；把问题投影成英文后多数只剩「GVP Module XV」「ICH E7」这类文件编号，词法通道对英文分块仍找不到 gold（24 题中仅 2 题进词法前 20）。真正的解法是把问题翻译成英文再检索（受限模型调用，或离线翻译索引）——基线把「跨语言检索」明确列为 P2（`ENGINEERING_BASELINE.md` 第 439 / 559 行），是否提前做需要决策人定。

## D. 需要决策人决定

1. **跨语言检索是否从 P2 提前**。方案 (a) 查询翻译：检索前一次受限模型调用（gpt-6-luna，输出只作为第 4 条查询进入 multi_query 融合，不生成任何过滤条件；约 0.0002 美元 / 次，时延 +1 秒左右），作为可发布参数 `query_translation`，评测 6.4 美元；预期覆盖子集约 22 道失败题。方案 (b) 离线把英文语料翻成中文只用于词法匹配（一次约 2–3 美元 + 摄取改造）。方案 (c) 维持 P2，本轮不做。我建议 (a)。
2. **文档定位候选（P0 内）**：点名产品 / 文件的问题优先该文档。离线估算：60 道失败题中 30 道在问题里点名了语料中的文档或产品（27 道唯一对应），29 道的 gold 就在被点名的文档里，其中 22 道目前是召回 / 重排失败——在一份 20 页文档的几十个分块里找 gold，向量通道即使跨语言也容易得多。先零费用复测，再与词表 + multi_query 合成一个检索候选评测（6.4 美元）。**建议先做这个**，它比翻译更便宜、在 P0 范围内、且覆盖的题数相当。
3. **生成阶段修正**（校验规则极性、提示词「禁忌即答案」、裁判附问题）是代码改动，会改 `model_config_version`；为了不重跑 baseline 臂，运行器需允许「仅被测组件版本不同」的 baseline 复用并在报告里写明——是否接受这种对照方式。
4. 余额约 16 美元：第 2 项一次评测后约剩 9.6，第 1 项 (a) 再一次后约剩 3；建议充值后再做第 3 项。

| 他文档同句：回答内容正确，但引用的是另一份含相同句子的文档 | rp-0053, rp-0194, rp-0236, rp-0325, rp-0535, rp-0536 | 全集机械核对：39 道「错引」中 14 道的被引分块逐字包含标注的 key_text，逐一核对后**没有一道是同文档的重叠分块**，全部是另一份文档：同成分他牌仿單（拔痛酸 / 痛風停 allopurinol、胃所樂 / 怡胃適 esomeprazole、穩壓 / 緩壓 losartan）、FDA 申办方 / 研究者两份安全报告指南的共用段落、ICH 原版与 FDA 转载的 E6(R3)、GVP Module VI 引用的 E2A 定义。问题点名了具体产品或文件，系统却引用了「双胞胎」文档，标注判错是对的（不同许可证持有者的仿單可能不同）。这是检索的文档定位问题（drug_name_zh、protocol_id 切片），不是标注缺陷 |
| 裁判过严 / 裁判看不到问题 | rp-0012（问题限定 CrCl < 30，答 400 mg 正确，裁判以「另一档是 800」判矛盾）、rp-0174（"may request" 与问题里的「应」被判矛盾）、rp-0222（陈述省略了条件，裁判判矛盾，属边界） | 与记录 54 §3.5 的 rc-0002…0005 同源：裁判缺少问题上下文；已列为 ADR-0011 候选 |
