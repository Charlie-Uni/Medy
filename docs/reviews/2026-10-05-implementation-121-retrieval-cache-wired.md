## 1. 更正

M1-19 的缓存组件在 2026-09-20 完成并通过测试（记录 39）：键含权限指纹与版本、命中后仍回查、按部门纪元失效、进程内与 Redis 两种存储。但之后搭建的问答链路与 API 运行时**从未调用它**：`ProductionRetrieval` 直接查库。记录 77 的环境表里写过一句「M1-19 的缓存未接到 API 运行时」，实现方没有把它作为缺口提给决策人，路线图该行一直写「已实现」。这是实现方的疏漏；路线图已改为写明「组件 9 月 20 日完成，10 月 5 日才接入运行时」。

顺带一个事实：Redis 在此之前没有任何运行时用途（任务队列在 PostgreSQL），只是被部署和配置着。

## 2. 接入方式

- 设置 `RETRIEVAL_CACHE`：`off`（默认）/ `memory`（每个 API 进程一份）/ `redis`（经 `REDIS_URL` 共享）。`off` 时检索路径与此前逐行相同的结果（见 §3 的核对）。
- `ProductionRetrieval` 新增可选参数 `cache` 与 `cache_versions`（检索版本、策略版本）。API 运行时按设置构建缓存并在每个请求里传入该请求的版本——灰度两侧的策略版本不同，所以各用各的条目。评测与回放工具不传缓存，不受影响。
- 键：规范化问题、部门、权限指纹（部门 / 角色 / scope，不含用户 id）、会话上下文指纹、as-of 日期、历史标志、复合检索版本、策略版本，再加部门纪元。
- 值：融合后的候选清单（≤ 20 条），以及**写入时重排模型对通过复核的候选给出的顺序**。
- 命中路径：在提问者的身份连接里对缓存的每个候选逐块复核（可见性、版本状态、as-of、内容哈希）→ 按缓存的顺序取前 8 条。不搜索、不调用查询翻译、不调用重排模型。
- 未命中路径：与此前相同，完成后写入缓存。
- 存储故障降级为未命中，不报错（组件原有行为）。

## 3. 为什么要缓存重排顺序

第一版只按记录 39 的设计缓存候选清单。在真实语料上一量，命中只省 0.08 秒：一次检索约 3.7 秒里搜索只占 0.1 秒，其余几乎全是重排模型。于是把重排顺序也放进缓存值。这样做的安全论证：

1. 证据仍然只来自复核。缓存里的顺序只用于给刚刚通过复核的证据排序和截取，不能让任何一块未经复核的内容进入证据。
2. 重排分数只取决于（问题，分块正文）。问题在键里；正文若有变化，复核的内容哈希检查会先把该块拒掉，旧名次无从作用于新正文。
3. 重排模型的版本与输出条数在复合检索版本里，变了就是另一个键。
4. 被撤权或归档的块从结果里消失后，其余块的相对顺序就是对剩余集合重新重排会得到的顺序（分数逐块独立）——有单元测试。
5. 缓存条目不含顺序，或现在通过复核的块不全在缓存的顺序里时，照常调用重排模型。

## 4. 核对

**真实语料等价性（本机检索，不调模型 API，查询翻译关闭）**：从全量运行 F2 中按间隔取 120 题，逐题做三次检索——不带缓存、带缓存首次（未命中）、带缓存第二次（命中）。

| | 结果 |
| --- | --- |
| 三次的候选清单、证据 chunk、顺序、正文完全一致 | **120 / 120** |
| 检索耗时中位数 / P95：不带缓存 | 3.90 s / 6.08 s |
| 未命中 | 3.99 s / 5.94 s |
| 命中 | **0.043 s / 0.050 s** |

每次命中省约 3.9 秒；生产配置下还会再省一次查询翻译调用（本次核对里关着，未计入）。

**单元测试**（`tests/unit/harness/test_retrieval_cache_port.py`，6 个）：不带缓存时每次都搜索；命中跳过搜索与重排、结果与未命中相同、且确实走了复核；被撤权的块在命中路径上消失、其余顺序正确；部门、问题、策略版本、检索版本、纪元任一不同即未命中；无顺序的旧条目照常重排；缓存缺版本信息被拒绝、存储故障降级为未命中。组件原有的集成测试（真实数据库上的撤权、换版本、Redis 存储）未改动，照常通过。

## 5. 失效

发布、归档、撤回文档后，`make cache-invalidate`（`python -m medops.retrieval.production invalidate-cache`）消费发件箱事件并提升相关部门的纪元，这些部门的条目立即失效；只对 `redis` 模式有效。不运行时条目在 `RETRIEVAL_CACHE_TTL_SECONDS`（默认 300 秒）后过期，其间新发布的文档可能检索不到——权限与版本的正确性不受影响，因为命中路径仍然复核。`memory` 模式没有跨进程失效。已写入 DEPLOY.md 与运行手册 6.4 检查单。

## 6. 它不解决什么

- 只对「相同问题 + 相同权限 + 相同版本」的重复提问生效。评测集与性能测试里每题不同，命中率为零，验收报告里的 P95 数字不会因此改变。
- 没有真实流量，命中率未知；所以默认关闭，不在本记录里声称任何线上收益。
- 作答与校验的模型调用不在缓存范围内。
