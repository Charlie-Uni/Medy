# PV Agent 逐项终检与内部审核材料

记录218；AGENT-05的内部材料切片，本切片工程自审通过。前置是已完成的[执行契约](AGENT_RUNTIME.md)、[行动与验收](PLAN-02-action-budget-and-acceptance.md)以及ARCH-04/11。记录219已补业务终态、澄清/升级资料交付；关联新执行仍SESSION，详见[终态契约](AGENT_TERMINALS.md)。

## 1. 输入和责任

可信Driver读取持久保存的`finish`动作、原任务要求、原叙述及实际证据注册表。模型提出草稿，不能传入可信证明或自行授予业务完成状态。`AgentExecution.review()`返回受限的`PreparedReview`，表示已保存的审核材料；`completion_eligible`是内部候选资格，不能充当业务`completed`或对外答复授权。

本切片不改目标、评分器、gold、来源白名单、公开Schema、默认模型、生产策略或原验收门。启动仍需可信服务显式配置最终检查包络，无生产数值默认值；托管运行继续逐次授权。

## 2. 两层核验和逐项要求

1. 结构层核对已知要求及类型、必需项覆盖、真实Unicode原文区间。允许同一要求含多条事实或陈述。可选项缺失可以明示，不能因此单独否决；未知ID、错误类型、虚假引用、同时宣称已覆盖与缺失均拒绝。
2. 原引用验证器保留。它的真实请求、原重试上界、事实查询、预算和调用回执没有被新判断替换。
3. 最终材料模型获得原叙述、要求、草稿和每个实际使用句柄的完整可见原文/引用。数据都是不可信材料，不能作为改权限、阈值或提示的指令。未传评分器预期、隐藏gold、其他任务或未使用来源。
4. 最终模型分别判断叙述支持、业务完整性和范围安全；为**每个要求**返回完整性，为**每条指南陈述**返回支持判断及支持组。布尔值必须是真布尔，每个要求/陈述恰好一行；遗漏、多余、重复、跨陈述句柄、旧版回复、重复JSON键和截断回复均不通过。
5. 可信编译器重新核对原动作/任务/草稿/策略摘要和回执，重算派生结论。`complete=true`不能覆盖必需项的`complete=false`；新支持判断不能覆盖原引用失败；本地输出安全规则不能被模型的`scope_safe=true`覆盖。

模型语义是否准确仍须获准真实运行与校准。本轮使用公开合成数据和离线脚本回复验证执行机制，不能宣称医学质量已通过。

## 3. 多块证据：AND/OR

每条陈述的`support_groups`例如：

```json
[["handle-A", "handle-B"], ["handle-C"]]
```

真实字段是UUID。组内是AND：A、B共同提供完整定义/条件，不能将A单独当作足够证据。组间是OR：C是另一套独立足够的证据。单元素组必须自己足够。模型只可使用这条陈述自己引用的实际句柄；无支持或矛盾时支持组必须为空；重复/空组、重复句柄和其他陈述的句柄被拒绝。

这些组由最终模型从实际可见材料判断，是运行时的支持声明，**不是评测gold**。系统保存组及每个实际原文、原文哈希、源文件哈希和Citation，供人核对。它不证明模型判断天然正确。

## 4. 审核材料与失败

`PreparedReview`版本为`pv-review-material-v1`，绑定原执行、动作、草稿和最终策略，保存要求状态、分项门结果、通过核验的事实/指南陈述、完整支持组、原文证据及逐调用回执ID。

| 情况 | 材料结果 |
| --- | --- |
| 全部原适用门和必需项通过 | 内部`completion_eligible=true`，仍不写业务终态 |
| 必需项实质不完整 | 状态`incomplete`，资格失败；不把“有ID”当完整 |
| 陈述未支持/矛盾 | `not_supported`/`contradicted`；移除该陈述及不再使用的证据，原草稿留在受限审计 |
| 叙述整体语义失败 | 不复制叙述事实；原文不作为未验证答案回退 |
| 模型或本地安全规则失败 | `withheld`；不复制草稿正文 |
| 结构层已缺必需内容 | 不调最终模型；结构化记录缺失，语义/安全/引用门为`not_run`，不伪造裁判结果 |
| 供应商/预算/权限/审计异常 | 抛出失败，不能伪装为完成或正常无答案 |

相邻证据、数字、单位、否定、适用条件和未知信息属于实际语义核验范围；本轮没有靠手写生成事实来修补缺口。澄清与升级动作的材料规范和原子交付已由记录219的[终态Owner](AGENT_TERMINALS.md)实现，编译器接口本身不授予发布权限。

## 5. 事务、恢复与权限

原检查完成后，Driver在**同一最终事实栅栏事务**追加完整检查/受限审核材料并更新head，确认提交后才向内部调用者返回。正文沿用0029的加密事件、AAD、保留边界与部门RLS，没有新增迁移或扩权。原请求/回复、失败费用及回执保留。

同一实例重复读取复用已提交材料；重新领取原租约并恢复原执行后，只接受唯一已认证的材料事件，校对原动作/策略/句柄内容和实际持久回执。每次读取仍检查当前身份、版本、来源、事实、取消和持有权。闭合最终阶段不能再次发送模型请求；有回复但没有完整材料提交的情况停止，不能靠重试猜测原结果。

提交失败和确认丢失都不返回未确认材料；如果数据库事实上已提交，后续恢复可复用那个已认证事件。若未提交，只保留实际调用/费用并失败关闭。已保存的旧审核材料不意味着当前仍可向外发布；业务发布由记录219终态Owner取得新的最终输出栅栏，并原子保存业务终态。
