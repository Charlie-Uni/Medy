# PV Agent 业务终态、澄清与升级交付

记录219，AGENT-05。八项工程自审通过，AGENT-05工程DONE；真实质量/部署另验。依据[PLAN-02](PLAN-02-action-budget-and-acceptance.md)、[逐项审核](AGENT_REVIEW.md)与[持久运行](AGENT_RUNTIME.md)。业务目标和验收口径保持，无新目标裁决。

## 1. 入口和边界

可信服务的`AgentExecution.execute()`运行动态循环并调用终态Owner；诊断路径可分开`run()`、`review()`、`finish()`。`run()`仍返回内部handoff，不能凭其reason=completed报告业务完成。`finish()`只根据持久的原动作、观察、真实最终核验和当前权限生成结果，**确认业务提交后**才返回`AgentDelivery`。模型不能传入已批准材料或直接写终态。

`AgentRuntime.result(context, user=authenticated_user)`是无模型、无执行根的读取入口，必须显式提供已认证身份，检查归属/当前目录身份/保留期，以及有正文结果的当前事实和策略。当前为可信服务内部接口；公开HTTP、完整轨迹/审计读取和回放仍AGENT-06。读取结果不恢复旧执行或授权付费。

所有者已确认的场景仍为合成PV叙述整理和指定指南核对，不判断因果、不提供个体医学建议、不对外上报。RAG、Harness、Skill Registry、ACL与实际模型选动作保持。真实模型语义质量属于获准试跑和评测，工程测试不替代它。

## 2. 业务结果

| 状态 | 必要条件和可交付资料 |
| --- | --- |
| completed | 原finish草稿的叙述、逐项要求、指定来源、引用支持组和安全全部通过；原预算/绝对期限/持有权和最终事实栅栏通过，材料/审计/控制封闭同事务提交 |
| awaiting_clarification | 原clarify问题经过独立于规划的实际模型调用核验：阻塞任务、确实缺失、措辞有依据且安全；明确的问题、未完成项、已核验提取信息及原调用/费用引用已保存 |
| escalated | 原finish最终核验未通过，或有依据的escalate/安全/无进展/步数停止；保留可交付的核验结果和缺口，创建pending_review升级回执；不宣称已分配人工或已对外上报 |
| failed | 供应商/判定格式/预算/超时/依赖/恢复等系统失败，不能当正确无答案；保存可确认的原调用与保守预留、失败原因；不返回未核验草稿 |
| cancelled | 当前所有者取消，保存取消回执并停止；不继续模型调用、补做推理或交付旧草稿 |

`AgentTerminalMaterial`含逐要求状态、必需缺口、实际审核材料、通过核验的问题/提取要素、已提交动作摘要、已有回执/无回执在途调用ID、升级回执及原免责声明。`same_run_resumable=false`；澄清时`continuation_mode=new_execution_required`，其余not_applicable。

回执存在不等于usage已知；原实际/保守费用在冻结预算与逐调用审计中保留，不把超时未知金额写成零。

升级回执`state=pending_review`、`assigned_to=null`、`externally_reported=false`。本轮只建立真实持久的待处理材料与读取，人工分派/处理工作台仍HANDOFF-01/02。

## 3. 澄清和升级的实际核验

最终材料策略为`pv-final-material-v3+terminal-delivery`，增加停止判定提示/严格Schema和显式尝试上限配置，进入原策略摘要。finish的逐要求/逐陈述AND/OR核验不删除。

clarify/escalate使用同一原根、原准入判定模型和封闭最终阶段，最多一次`agent_final_stop`调用。输入仅为原叙述/要求/来源、原动作、已提交工具请求与合法观察、实际可见证据；不传gold、评测预期或身份凭据。不向判定模型复制无关绑定、回执/哈希等观察元数据；完整原观察仍在加密审计。证据不截断以凑包络。

严格判定包含decision_supported、scope_safe、narrative_supported及每个问题的necessary/grounded；要求字段集合恰好匹配，不接受重复/遗漏/额外字段、字符串布尔、截断或重复JSON键。已解析的来源/版本不能再次提问；模型不能谎称已达步数/连续无进展或凭空制造来源歧义。其余业务必要性必须由实际模型按材料判断，不能以规则归因代替。

问题或理由不成立时不返回awaiting_clarification。范围或本地安全检查失败时不输出问题/草稿。escalate草稿中的指南/患者断言不会未经完整审核就复制到交付；已有真实AE提取只有在最终叙述支持检查通过、原文区间一致且本地输出安全通过后才保留。未获核验支持则移除，原审计保持。

停止模型返回后立即重查真实预算与deadline，最终持久对账仍有blocked或在途调用时不发布成功/澄清材料。实报费用和Token超额原样保留。

自动预算/超时/依赖停止不调用额外模型“补救”。核验或存储故障按失败处理，不伪装成来源没有答案。

## 4. 原子性与数据库封闭

migration **0030**只增加`agent_run_control`的terminal_ref/terminal_at/terminal_status和写入守卫，没有改既有Task枚举、角色授权、冻结集或发布策略。仅临时测试库升级，正式本地三库仍0026，未部署/重启。

1. 规划/工具/最终模型均不持有控制行锁跨供应商操作。实际请求与回执沿用原write-ahead/结算审计。
2. 原最终检查可先保存为不可变审核事件；业务发布再取得当前身份、来源和完整事实的同事务栅栏，重查原租约与原绝对预算截止。
3. 仅冻结一次原预算；后续清理取得当前账目快照，保留迟到结算，不再次冻结或重开额度。
4. 最终执行head快照、加密业务结果事件和控制封闭标记在一个事务内保存。提交确认前不返回completed。head继续表示最后执行快照，**控制封闭标记指向的业务事件才是权威终态**。
5. terminal_ref必须指向同run/身份/部门/原租约的真实不可变事件；空引用、其他run或无结果封闭被数据库拒绝。非失败/取消结果在最终seal仍须满足原head预算截止、原租约和未取消条件，Python与SQL分别检查。
6. 终态后数据库拒绝再领取/续租/消耗步数、修改执行head或准入新模型请求。即使旧代码没有新模块检查，SQL守卫仍禁止继续推进。原已准入请求的迟到费用与故障回执可追加，不能覆盖业务终态。
7. 存在已封闭执行时0030降级拒绝，防止降级丢失停止状态后重新打开旧执行；未使用终态的空库仍可正常往返。代码回滚也须保留数据库封闭守卫。

`TerminalRecord.material_ref/audit_ref`是业务事件的逻辑item_id，按run/kind/item_id唯一定位其材料与回执；verification_ref指实际最终检查event_id；控制terminal_ref指实际业务event_id。材料摘要与原context/执行/预算/支持组绑定，读取时重新校验；verification_ref指向的同run真实checkpoint必须仍存在，且其审核材料或停止判词与业务材料精确一致。缺失、改指或内容不符不返回旧完成。

## 5. 故障、恢复与竞态

| 情况 | 行为 |
| --- | --- |
| 最终检查已提交，业务结果未保存 | 原期限内可恢复原检查与原动作，重新原子保存；不重发任何模型核验 |
| 业务提交回滚 | 不返回完成；保留失败审计，复用已确认最终检查后可保存 |
| 业务已提交但确认丢失 | 原请求仍报保存失败；之后只读取得实际已提交结果，不重跑模型，不能再创建执行根 |
| 已知模型回复但没有完整最终检查提交 | 失败关闭，不以重发猜测旧调用结果 |
| 取消与保存并发 | 控制行锁给出确定提交顺序；先取消则只保存取消，先业务提交则终态不可改写 |
| 归档/ACL/来源文本/版本变化 | 最终同事务检查或读取复查拒绝正文，保留故障回执；不借别的来源替代 |
| 旧所有者失租 | 不写新持有者的终态或head；只可保存受限迟到故障/费用事实 |
| 已撤权、数据库不可用或审计写入也失败 | 不返回未经确认结果；尽可能追加metadata-only保存失败回执，不能承诺存储不可用时仍有可读业务终态 |
| 原预算期限短于125秒 | 按head绑定的更早预算截止处理；财务清理余量不能延长成功发布的期限 |
| 多个句柄来自同一未变chunk | 完整比较事实后按chunk去重再做栅栏检查；不同内容不静默择一 |

## 6. 显式尝试上限和预算

8决策步、12,000 Token、0.60 USD、125秒及原最多3attempt保持；模型/价格表/ACL/已发布策略未改。

`FinalGateConfig.citation_attempts`默认3，可信服务可显式选择1或2，不能超过3或由模型设置。实际Registry NodeSpec、预算计划、startup预留、操作key/受限审计都使用实际较小上限；普通Skill/旧Agent路径默认None，保持原重试与旧operation key。材料终检/停止判定各仍最多一次。

这是显式缩小重试机会，失败直接停止，不增加余额或删除必需证据。双块联合陈述在原验证器中需要真实语义调用；公开工程例子使用最多一次引用尝试及实际字节包络，完整执行并保留两块证据。配置很宽、重试预留很大或工作量增加时，仍可能在规划/提取前或中途预算停止；不保证走满8步。没有生产包络数值默认值，示例配置不作为真实可完成率证据。
