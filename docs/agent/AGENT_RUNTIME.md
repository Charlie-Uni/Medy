# PV Agent 持久执行与恢复

2026-10-17，AGENT-04，记录217。本文描述工程机制；真实模型质量、业务终态发布、HTTP入口及部署分别验收。

## 1. 装配和责任

- `application/agent_loop.py`：每次让模型选择一个动作，根据实际观察继续决策。七动作、8个决策步、连续两次相同无进展停止不变。
- `bootstrap/agent_services.py`：真实装配当前路由、原Skill注册表、BM25/向量检索、翻译、缓存、重排、事实库身份、当前目录和版本检查。必须显式提供规划配置、真实终检配置、租约周期及受限材料密钥。
- `bootstrap/agent_execution.py`：拥有原根预算、持久租约、心跳与执行生命周期。`start`只接收全新执行；`recover`只恢复同一身份/条件下已经存在的执行。
- `bootstrap/agent_driver.py`：调用前写入、实际回执、完整观察和恢复状态的事务边界。结果提交成功后才能成为下一次规划的观察。
- `infrastructure/db/agent_runtime.py`：0029的加密head和追加事件；0027负责持有权/取消/原步数；0028显式预算交接仍保留，真实Driver不依赖进程正常退出才能保存费用。

可信服务先用 `bind_new_agent_context` 为**新执行**绑定当前事实/策略/提示/工具/终检及工程profile；再通过 `production_agent_runtime` 构造运行器。不能用绑定函数为旧执行换条件。公开入口及人工澄清后新任务归AGENT-05/06和SESSION；模型不能调用这些可信装配接口。

## 2. 持久边界

1. 决策开始时，在同一短事务中消耗原步数、保存原请求UUID及规划子期限。
2. 每个实际模型调用在供应商操作前，把原请求、原预留和完整根预算写入并确认提交。写入失败或提交确认不确定，均不进入供应商操作。
3. 供应商返回或异常后，保存逐调用回执、已知/保守费用及实际SDK审计。取消、撤权、超期、失租后的迟到回执仍可以追加财务事实，不能推进旧head。
4. 工具最后的事实检查、完整工具审计、已接受观察和新head在同一事务提交。提交确认前不向循环返回观察。
5. 退出时永久冻结旧根。可持有且未过期时释放租约；失租、撤权或取消不覆盖新持有者状态。恢复必须先完成新代租约领取和head提交，之后才创建可用执行根。

规划、提取和引用供应商操作不持有Agent控制行锁。原检索实现中翻译与独立检索事务可能重叠，未声称本轮完成整个RAG事务拆分。

## 3. 恢复矩阵

| 已持久阶段 | 同一原执行的处理 |
| --- | --- |
| 决策已消耗、没有调用准入事件 | 证明没有进入供应商后，可发送原UUID的第一次调用；保留原步数和原子期限 |
| 规划回复及回执已确认 | 复用原回复，执行原决策，不再调用规划模型 |
| 工具结果与head已提交 | 重建提取结果、证据注册表、规划板和重复计数，进入下一决策 |
| 只有调用准入，尚无回执 | 保留全部预留和原ID，失败关闭；不重发未知请求 |
| 工具曾准入模型调用，却没有完整工具结果 | 费用对账后停止；不重跑整个工具以猜测旧执行是否成功 |
| 旧持有者失租后才追加回执 | 可将原pending对账为实际费用，但不接收旧持有者的规划进度 |
| 保存了handoff | 返回原停止原因/原终态申请，不重开循环；`completed`在内部表示finish申请，不是业务完成 |
| 最终阶段active / closed | active恢复后封闭并阻止重跑；closed保持封闭，已有终态申请可交接，禁止再次核验或普通模型调用；记录218允许复用唯一已提交且重新检查当前权限的内部审核材料，不重发模型 |
| 控制已封闭terminal_ref | 拒绝恢复成可执行根；走当前身份/事实/保留期复查后的无模型结果读取 |
| 超过原绝对期限，或绑定/权限/密文/账目链不符 | 不返回可执行实例，不另发额度 |

不承诺供应商恰好一次。提交确认丢失可能造成保守预留无法立即释放，这是明确的失败关闭边界。没有供应商回执不能把未知费用写成零。

## 4. 原预算与期限

12,000 input+output Token、0.60 USD、125秒、原重试上限保持。head保存accounted/known/pending/settled、原限额、保护额度、原最终槽位和绝对预算截止。恢复时间扣除停机时间；规划和工具还保留自己的原子期限，不能重新领取20/60秒。

所有调用都绑定run/trace/call/attempt及decision/action/final。恢复核对整个调用准入集合与预算pending/settled集合，以及已知/保守费用、Token和调用数；只相等四个累计数不构成恢复凭证。旧根永久挂起，ContextVar嵌套和线程不能替换原预算或journal。Agent按既定契约顺序调用模型；并发第二个模型准入失败关闭。

## 5. 启动终检预留的真实来源

`FinalGateConfig`是可信服务的**必填工程配置，没有生产默认数字**：终检沿用已准入判定模型，明确输出上限、总user数据字节上限、最多引用判定数及每次引用判定的数据字节上限。

`startup_reserve`复用真实最终材料提示/JSON Schema和原`claim_judge_request`模板。UTF-8输入、Schema、framing与输出使用原共享预算估计器，费用使用实际网关价格表；引用部分乘原Skill最多3次attempt，材料终检一次、不增加重试。计算结果必须放入原12,000/0.60上限，否则启动拒绝。不可连空草稿加原叙述/要求都放入输入边界的配置，也在启动前拒绝。

这不是虚构usage或预先生成事实。未知草稿没有被填入假证据；配置限制的是**真实最终请求可接受的字节包络**。终检前用实际草稿、实际证据和原请求构造器再次完整预检，超过任一包络就停止，不裁掉必需信息来凑额度。包络较窄会降低可完成率，真实可完成率需单次授权试跑验证；不保证走满8步。

为让推导绑定真实执行，本轮同时实现AGENT-05所需的共用材料核验：结构覆盖、Unicode原文引用、现有安全检查、原逐条引用验证，以及叙述语义/业务完整性/范围安全的独立模型判断。`driver.verify_final`使用同一原根的封闭最终阶段，保存内部证明。它不会写业务completed、不会发布、不创建HTTP入口；记录219终态Owner已补终检失败映射、完整结果和业务终态原子保存；本接口本身仍不发布，AGENT-06完整轨迹/公开入口继续推进。

## 6. 正文、权限和兼容

0029新增head/events两表。正文使用现有envelope加密，AAD绑定run、条件摘要、修订、租约或事件身份及预算摘要。普通遥测只有既有metadata边界，不写叙述/证据/请求正文。head最多20MiB明文、预算metadata2MiB、事件最多512条/模型调用最多128条；超限停止，不能截断成功。

新增表强制部门RLS；应用仅有必要读取/追加/head更新权限，事件不可更新，普通角色不可删除。受限保留角色只能读取/删除已过保留期的数据，保留时长来自显式配置。没有给既有表扩权。完整面向人的审计读取、轮换/清理调度和业务Trace入口仍按AGENT-06推进。

循环私有格式升级为`pv-loop-state-v2+terminal-admission-budget`：额外保留终态申请当时的预算，使之后扣除终检费用不会改写原准入历史。旧v1私有图像拒绝，不静默补字段；此前没有部署正式持久Driver。公开36个Schema、冻结数据、gold、默认模型和发布策略保持。0027～0029只在临时测试库升级；正式本地三库未迁移或重启。
