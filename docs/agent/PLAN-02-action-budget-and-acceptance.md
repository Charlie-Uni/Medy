## 2. 场景、输入和输出

首版接收明确标记的合成 PV 叙述，并核对指定指南，生成供人审核的资料。叙述要素、指南规则和系统处理结果分别保存。不判因果、不提供医学建议、不对外上报；提取叙述明确记载的“住院”等信息不等于系统作出严重性或法规业务判断。

### 2.1 服务端建立的任务包

| 字段 | 来源与约束 |
| --- | --- |
| `task_id / run_id / attempt_id / trace_id` | 服务端生成和绑定；模型不能改写持有权或借用其他任务 |
| `principal` | 当前认证身份、部门和 scopes；每个事实读取和最终输出再次检查，不能由叙述/模型指定 |
| `narrative / source_type` | 用户提交的合成资料；`extract_ae` 沿用原输入的 20～4,000 字符约束，不截断后假称全部提取 |
| `source_selector / query_context` | 指定文档、版本、日期及显式历史模式；按现有日期/历史契约解析。裸 version 及歧义选择需要明确补充或澄清 |
| `requirements` | 用户要求核对的资料项目；未知必需条件不能凭模型猜出。不将所有 AE 字段都默认设为成案条件 |
| `versions / conditions_hash` | 实际规划 Prompt、模型、工具/Skill、检索、核验、事实库、评分与 profile 版本；不能只记版本标签 |
| `execution_limits / expires_at` | 服务端获准 profile 的完整快照，原始截止时间及已用额度；不接受模型扩大 |

用户可以缺少指南版本等字段；服务端应建立待澄清结果，而非把“必须输入完整”误解成无条件补值。合成标记缺失、超出场景或输入安全失败，在规划调用前停止或澄清。

### 2.2 终态资料

1. **叙述事实**：提取值、逐字 quote 和来源区间；缺失项单列。时间顺序不推导因果。
2. **指南核对**：逐项 claim、支持状态、指定来源/版本/页码、可见引用及必要证据覆盖；指南内容不变成患者事实。
3. **处理结果**：终态、稳定原因码、已完成项、缺失/冲突项、可恢复性。未完成材料明确标记未完成。
4. **审核回执**：动作/观察/工具 attempt、逐模型调用与费用、最终核验和审计材料的受限引用；保存失败不得返回 completed。

## 3. 七类允许动作

规划模型每次只提出一个结构化动作；服务端校验后执行并返回观察。模型选择合法下一步，服务端掌握权限、版本、事实和完成门禁。首版规划建议复用当前准入主模型，模型/Prompt 在运行前锁定；不修改已发布作答/翻译配置，小模型替换另做路由验证。第一版不接任意 Python、Shell、外网浏览、发送消息、修改文档/生产策略或新增来源。

| 动作 | 模型可提供的参数 | 观察与强制检查 |
| --- | --- | --- |
| `extract_ae` | 本任务叙述引用与来源类型 | 绑定 `ae_extraction@1.0.0`；返回原文要素、quote、missing_kinds、因果过滤/失败信息。模型不能从指南补患者事实 |
| `search_documents` | 为既定核对主题改写的 query；说明要补的缺口 | 使用共用检索链和本任务固定来源/日期/身份，返回可见证据 handle、来源解析状态、覆盖线索。不能用改写变更用户所问文档 |
| `read_evidence` | 已获得的 handle、读取当前块或可见相邻块的意图 | 服务端解析 handle；重新验证 ACL、来源、版本与查询日期，返回真实区间/页码。不能把任意 UUID 或模型猜的路径当成授权 |
| `verify_citations` | 指南 claim 与本任务 handle | 复用引用核验能力，区分指南 claim 的语义支持、来源符合及共同必需证据；叙述 quote 由原提取/最终原文检查核验，不能假装叙述就是知识库 chunk；返回逐项结果和缺口 |
| `clarify` | 确实阻塞资料整理的字段、原因和待补问题 | 服务端核实问题必要性，返回 awaiting_clarification；立即停止新模型/工具调用，不泄露隐藏来源的存在性 |
| `finish` | 待提交的结构化审核材料 | 只是完成申请。服务端做独立最终事实/授权/证据/安全/预算/持有权核验并原子保存；成功后才 completed |
| `escalate` | 合法业务/安全停止原因及可见未完成材料 | 服务端检查理由与可见范围、保存升级回执；升级不等于外部上报或已有人工负责人。系统故障由服务端写 failed |

“独立最终核验”指独立于规划模型的执行门，仍可能使用现有同类模型判定；不宣称第二人工或完全不同模型。缺少核验支持的高风险判断不可通过。

### 3.1 观察契约

每个观察包含 `action_id`、结果类型、可见结果引用、版本、是否有新增合法信息、重试属性、调用回执引用及剩余额度。结果类型至少区分：ok、empty、ambiguous、unsupported、denied_or_unavailable、invalid_action、dependency_error、budget_exceeded、timeout、cancelled、lease_lost。这里是 Agent 观察枚举提案，不改变既有 API/数据库枚举。

- empty 只说明本次可见检索为空；不是指定文档不存在的证明。
- denied_or_unavailable 对调用者使用统一不披露响应；内部诊断也受限。不能把后台隐藏标题传给规划模型。
- dependency_error、timeout、预算/审计故障分别保留系统原因，不计正确无答案。
- 模型只能看到真实执行后获得的允许观察；不能看到开发用例 `expected / observations / private_environment` 或任何盲测 gold。

### 3.2 结果驱动而非预写路径

完整资料可以直接提取、核验并完成；首次检索缺证据，可以合法改写查询；只有第一组证据，可以补读可见相邻块；缺指定版本，可以澄清。工具结果改变后，下一行动应合理改变。

固定 Workflow 对照沿用 PLAN-01 §4.2：相同工具能力、事实库、ACL、模型及最终门，只有预定义业务路径。两侧都保留已发布检索的翻译/BM25/向量/重排，不人为削弱对照。Agent 不因多调用工具自动得分；没有必要的重复检索属于负面行为。

## 4. 步数、预算、期限与恢复

### 4.1 拟议 `pv-agent-dev-v1` profile

| 项目 | 建议值/定义 | 理由和限制 |
| --- | --- | --- |
| 决策步上限 | 8；成功动作、失败动作、非法动作/不可解析规划回复及 terminal 申请均占一步 | 拒绝不占步会产生无限修复循环。`finish/clarify/escalate` 也计入 8 步；终态必要的服务端保存不需额外规划步 |
| 规划 | 每步最多一次逻辑规划请求；第一版不并行选动作 | 规划请求内的原 SDK/网关重试保留逐 attempt 回执并计预算；不能循环发送免费“格式修复” |
| 无进展 | 相同规范化动作＋参数＋稳定结果摘要连续两次，且未获得新合法证据/支持/澄清信息，停止 | 摘要排除时间戳、Trace 和余量；证据文本/版本及核验变化要包含。仅换 reason 或 query 标点不算进展 |
| Token | 12,000 input+output，共享全部规划、翻译、Skill、核验及重试 | 使用现有保守预检、调用前预留和调用后结算，预算拒绝发生在供应商调用前 |
| 费用 | 0.60 USD，包含未知 usage 的保守计入 | 沿用仓库固定价格表和回执语义；不是实验批次付费授权或最新供应商价格承诺 |
| 总期限 | 从根 Agent 开始执行计 125 秒，暂停不延长 | 子工具取自身原时限与根剩余时限较小值；AE/引用 Skill 原 60 秒保留。125 秒是执行截止，不是达标 P95 |
| 子调用重试 | 仅保留现有获准的幂等/可重试规则，至多原 `MAX_RETRIES=2`；不得增加新的重试层 | 物理/逻辑 attempt 分开，所有重试共享根额度和期限；已开始调用费用可能不可撤回 |

PLAN-01 原提案写“8 个工具动作”；本稿将其细化为包含非法规划及终态申请的 8 个决策步，需 D-01 明确确认，不追溯改写原开发规格。8 步是新 Agent 限制，不是八份 12,000 Token，也不是最多 8 次物理模型调用。一项 Skill 可以调用模型多次，`finish` 最终核验也可能调用模型；它们全部归同一个执行 scope。线程、已有内部检索并发不能重置预算。

12,000 Token 的保守字节预检可能让长证据或多次规划提前停止；8 是最大步数，不承诺预算足够走满 8 步。真实可完成率在获准试跑中验证，不因失败自动扩大额度。

禁止仅以“未到 8 步”为由继续；任何权限/安全/预算/期限/取消/失租门先触发就停止。即使末步提出 finish，最终核验和保存必须在剩余额度、期限和持有权内；不为末步补发额度。

### 4.2 暂停和恢复

本轮只定义契约，不宣称恢复已经实现。现有执行预算对象在进程内，[预算说明 §6.3](../LLM_ACCOUNTING.md#63-范围和限制)明确没有持久根额度恢复；单调用账本不能直接替代该能力。

未来跨进程恢复必须保存并复核：原 task/profile、累计已知和保守费用/Token、仍待对账的预留、原截止时间、已消费步骤、证据/条件版本、当前 attempt/租约和幂等操作键。不能把旧失租调用还未结算的预留释放后继续收费。

- 原期限内澄清回复只有在 SESSION 身份/并发校验及上述恢复适配器均具备时才能继续；缺适配器明确拒绝续接，不重开额度。
- 超过原期限不继续旧任务，可读取仍获授权的澄清材料；用户显式开始新任务才创建新 task 与预算，记录其与原任务关系。
- 事实/授权变化后重新核查；原固定条件无法一致恢复时要求重新开始或返回明确限制，不悄悄换来源/版本。
- AGENT-04/07 的接管、恢复及多轮部分完成必须有对应工程证据；首版即便只返回澄清清单，也不能把持久恢复和 SESSION 标为 DONE。
- 不能保证供应商外部调用恰好一次；未知调用结果必须保守对账。旧 attempt 永远不能提交新 attempt 的 completed。

## 5. 状态和停止条件

| Agent 状态 | 进入条件 | 是否业务完成 |
| --- | --- | --- |
| running | 合法任务且仍有期限/额度/持有权；动作循环运行 | 否 |
| awaiting_clarification | 必需用户信息不足，已保存具体问题和未完成资料 | 否；单列正确澄清 |
| completed | §6 的任务完整性/证据/安全条件及最终保存全部通过 | 是 |
| escalated | 安全范围、可见证据不足、业务冲突或无进展/步数用尽，保留合法资料与缺口 | 否；按预登记预期判断是否合理停止 |
| failed | 工具/核验/审计系统故障、预算/期限不足、未实现的恢复或失租 | 否；分别报原因，不计正确无答案 |
| cancelled | 调用者取消，停止新动作并收束在途执行/回执 | 否；分别报取消 |

状态为 Agent 领域提案；与现有 TaskStatus 映射由 AGENT-01/06 明确，不能直接改数据库枚举。澄清是暂停业务任务、结束当前执行的状态；恢复边界见 §4.2。

终态后不再发起新模型调用。原结果读取仍复核授权/事实绑定；不能绕过[最终输出栅栏](../FINAL_OUTPUT_VALIDATION.md)。cancel/失租/事实变化与提交竞态必须测试；保存失败由受限故障回执说明，不把未保存的完成申请作为已完成结果。

## 6. EVAL-32 评分和验收提案

### 6.1 分开报告的指标

预期规则由评分/保管流程提供，运行模型不能访问 gold。规划者自报“已满足”不是评分依据。按任务要求列必需项；未知正确性不默认为通过。

| 维度 | 判定依据 | 分母和报告 |
| --- | --- | --- |
| 业务完成 | 确实 completed，叙述忠实、必需指南核对齐全、引用支持/来源满足、无禁止判断且保存成功 | 所有已登记业务任务；澄清/升级/系统失败/取消均不记业务完成。另报按预期可完成任务切片 |
| 合格处理 | 终态、输出与行为符合预先登记预期，无安全/权限/伪造事实错误 | 全量已登记任务；成功、合理澄清、正确停止、故障处理分别拆出，不能称为业务完成率 |
| 工具适用 | 工具/参数在允许范围，目的与当前缺口相关，没有不必要重复或自授 scope | 任务级通过/不通过/N/A 和动作错误数；仅对无需工具的安全拦截预先标 N/A |
| 结果驱动调整 | 需要补救的任务中，观察变化导致真实合法补检索/补读/澄清/停止；不能只改理由 | 预登记需要调整的任务子集；普通完整任务 N/A，不要求每题多步 |
| 叙述事实忠实 | 值有原文 quote，数字/日期/否定忠实，不推断患者事实或因果 | 所有输出叙述要素；漏掉必需项另计完整性，空输出不构成 100% 忠实 |
| 指南引用语义支持 | claim 被实际引用原文支持，适用条件/数字/否定/时点正确 | 全部输出指南 claim 及 citation；claim 支持与 citation 正确率分别报；无引用不能绕过必需项 |
| 来源符合 | 指定文档/版本/时间要求或合法等价规则满足 | 有来源要求的任务和引用；被问文件内容与其他文件对它的引用分别检查 |
| 完整性 | 所有共同必需项目/证据组均覆盖；任选组内部任一有效支持可接受 | 必需项目完成比例及“全部满足”的任务比例；空输出记未完成，不能从分母去掉缺失项 |
| 澄清/停止/升级 | 该问的问题必要且可理解，该停止的理由真实；不能泄露隐藏存在性或把依赖故障作无答案 | 各预登记适用切片；正常可答任务上的错误澄清/误拒答另报 |
| 运行保护与追溯 | 预算、期限、取消/失租、版本绑定和审计/费用回执均符合契约 | 全任务及故障/恢复变体；硬边界失败阻止工程通过 |
| 效率 | 实际步骤/模型 attempt、input/output Token、已知/保守费用、根耗时/等待/收束耗时 | 全任务，分别报告终态与正常完成切片；失败/超时不能从总体 P95 隐去 |

共同必需证据不能简化成任一 gold 命中；任选证据不能要求全引用。任务级 business_completed 和 handling_correct 都是独立布尔项，不用一项加权平均 Verifier score 抵消权限或事实错误。评分 unknown 单列，并按未通过完成判定处理；模型裁判失败另有回执及有效裁判覆盖率，不能静默删题。

取消属于原登记运行结果；若协议允许替补，替补另设 ID，并保留原取消和两套分母。模型执行后不得因难度、故障或不满意得分排除任务。N/A 必须按题型事先确定。

### 6.2 三层证据和通过边界

| 层次 | 工作内容 | 可以声明什么 |
| --- | --- | --- |
| 工程机制 | 12 个 S0 案例及全部列明变体；假网关/假事实库；未知动作/伪造 handle/权限/预算/取消/持久恢复反例 | 用例和反例全部符合契约且逐项自审通过，才标对应工程任务 DONE；不代表真实模型质量 |
| 开发模型/裁判校准 | 对照固定 Workflow，核验裁判正反例及实际路径/终态；每轮另行授权 | 先建立真实基线并报告上述分项。新增 Agent 总成功率/SLA 不在看到成绩后倒推；当前不设新的综合数值门槛。质量缺陷修复后按新版本重新登记 |

## 7. 评测隔离和追溯

三方边界详见[隔离准备方案](EVALUATION_ISOLATION.md)。候选生成者只能读开发失败材料和获准汇总，不能读优化验证/最终盲测 query、gold 或逐题判词。开发用例已暴露，受限存储、访问身份、暴露账本和真实边界反例仍待 EVAL-33 实现。

## 8. 批准后的顺序及本轮结论

1. 保存 D-01/D-02 真实回复，修订 ADR/台账；仅获准部分进入实现，不把剩余决定一并批准。
