# Agent 持久取消与租约控制

任务：AGENT-04；实现与自审见[记录214](../reviews/2026-10-16-implementation-214-durable-agent-control.md)。这是内部控制层，尚未注册生产 AgentLoopDriver、公共端点或 worker。

## 1. 为什么单独保存

旧 `tasks` 执行单次 Skill，重试会增加 attempt；Agent 的一次执行还要保留原8步、125秒、上下文与预算。直接把 Skill 的重新领取当作 Agent 恢复，会丢失这些约束。新增 migration 0027 的 `agent_run_control`，保存身份/上下文摘要、原开始/截止时间、已消耗步数、取消时间和租约代数。它不保存叙述、证据、Prompt、答案或密钥，也不与旧 Skill `tasks` 建外键：两个 task 概念尚未接成公共服务。

**这张表不是完整恢复检查点。** 它没有完整费用/在途调用、规划板、观察、重复检查或最终阶段槽位。领取租约不代表获准重新调用模型；当前 AgentLoop 仍拒绝已有步数或已消费预算的恢复请求。不得通过新建零预算快照绕过。

## 2. 事务与调用顺序

实现：`infrastructure/db/agent_control.py`；装配辅助：`bootstrap/agent_control.py`。

1. 可信入口先完成身份、来源、版本、预算授权与启动前 profile；后两项完整 Agent 接线仍待后续。
2. 启动方沿用 `bind_fact_database` 提供的事实库 UUID/实际连接摘要；不向模型或工具传管理员连接，不给应用角色新增事实库身份表权限。
3. 用 READ COMMITTED 应用连接绑定部门，`create(initial)` 只接收 running、零步、零消费/在途预算的原始运行。重复插入报唯一冲突，不能重置旧记录。
4. `claim(lease_s)` 原子领取或接替过期租约；随机 `lease_id` 和递增 `generation` 共同标识持有权。时长必须有限且在 `(0,125]` 秒，实际有效期不超过原绝对截止时间。取消或超时不能再领取。
5. Driver 在 `decision_started` 的短事务内执行 `consume_decision(lease, expected_decisions=n)`，并保存相应审计后提交。只允许 `n→n+1`，重复/并发旧计数失败，第九步拒绝；领取和续租均不清零。
6. 把 `agent_lease_guard(...)` 作为既有 `call_scope(before_call=guard)` 的守卫。每次检查新开并关闭应用连接，检查当前身份、部门、上下文、事实库和持有权；嵌套调用继承原守卫，模型调用期间不保留数据库事务。
7. 工具/最终材料的真实保存必须在**同一个连接和事务**执行 `fence(lease)`、事实校验、审计与材料写入，再提交。`fence` 仅建立持有权边界，不替代事实校验、完整业务门或生产批准。

当前没有生产 Driver 自动完成第5/7项。测试用真实 PG 控制层连接既有模型循环及离线网关，验证这套协议，不把测试 MemoryLoopDriver 作为部署实现。

## 3. 取消、并发与时钟

- `cancel()` 是创建者身份范围内的持久、幂等取消，提交才生效。以后连接/进程仍能读到原取消时间；数据库触发器禁止清除取消标记。取消不清除历史费用或步数。
- 旧 lease ID/代数在新持有者领取后永久失效。检查、续租、消耗步数和提交 fence 都拒绝旧持有者，过期且尚未被接替的持有者也不能提交。
- 领取/续租/提交先锁行，**获得锁后**另读 `clock_timestamp()`，避免排队前的时钟判断在等待后继续有效；不接收客户端传入的“现在”。
- `fence` 的行锁持续到调用方提交/回滚，取消和接替必须等待。若材料事务先取得合法 fence，它先提交，后续取消才生效；若取消先提交，后续 fence 失败。这里的边界是数据库事务的串行顺序，不承诺撤回已经返回的内容。
- 已经发给供应商的请求不能保证撤回或恰好执行一次。返回成功保留真实 usage/cost；超时无 usage 保留原保守费用。检查失败后不能将其改写为未调用或免费重试。
- guard 是调用前检查，检查与网络发送之间仍可能发生取消；返回后的状态检查及写入 fence 必须同时存在。完整跨进程调用/恢复协议尚未实现。

## 4. 数据与权限

原表、原 ACL、默认模型、预算、Prompt/Skill/工具版本及36个公开 Schema 均保持。新表为 metadata-only：应用角色可 select/insert/update，RLS 强制部门；可信应用额外检查完整 principal 和上下文摘要。管理员业务角色只有读取权限，readonly/restricted/loop 无表权限；表所有者仍是可信运维者。

新表的 SQL 权限与旧 Task 一样信任应用服务，不声称能抵抗已经拿到应用数据库写凭据的攻击者。触发器额外阻止身份/原截止重绑定、计数回退/跳跃和取消撤销。未提供清理入口；保留/删除及受限材料存储要在 AGENT-06 一并实现，不能据此存入真实业务正文。

0027 仅在临时测试数据库执行。正式本地三库仍0026，未重启或部署；新入口不能在未迁移库上线。迁移回滚只用于尚无需保留记录的测试/准备环境；已有记录时不能直接降级丢失取消和步数。
