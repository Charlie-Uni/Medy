## 1. 当前证据和缺口

已有家族元数据盘点、三组相关家族示例、主集/安全集冻结和开发案例；没有新冻结盲测题、独立保管身份、外部封存存储或经过拒绝路径验证的盲测 runner。当前开发助手拥有工作区读取能力，不能因为给目录换名就称访问隔离已经成立。

258 份 active 文档只是未在限定扫描字段中出现的来源候选；暴露、译本/转载及近重复尚未穷尽，`blind_holdout_eligible` 仍未知。当前方案不改这个字段，不把全文从检索库移走，也不把公开文档的预训练暴露说成可证明不存在。

## 2. 角色与最小访问矩阵

角色可以由不同受限进程承担，不必是多个自主 Agent；同一模型供应商也不证明相互独立。隔离依靠实际访问控制、输入投影和结果出口；模型审查不能替代第二人工。

| 资料/权限 | 开发及候选生成进程 | 优化验证进程 | 最终盲测进程 | 所有者/保管流程 |
| --- | --- | --- | --- | --- |
| 开发失败 query/输出/合法证据 | 获准开发材料可读 | 可按协议读 | 不用于挑候选 | 可核查 |
| 验证 query/gold/逐题判词 | 不可读 | 可读、独立评分 | 不用于最终选题 | 可核查 |
| 盲测 query/gold/逐题判词 | 不可读 | 不可读 | 候选锁定后可读 | 可出题、复核、封存 |
| rubric/协议/数据版本/数量/哈希 | 可读 | 可读 | 可读 | 冻结和批准 |
| 验证汇总 | 仅预先允许的聚合字段 | 输出经检查的汇总 | 无需逐题诊断 | 可核查 |
| 盲测汇总 | 批次结束后读取允许结果；据此修复须记暴露 | 不作为优化选择反馈 | 仅完成锁定批次后输出 | 决定揭盲范围 |
| 可检索官方事实 | 经当前用户 ACL 可读 | 经当前用户 ACL 可读 | 运行时同样经 ACL 可读 | 许可/事实治理不变 |
| 评分器/门禁/生产指针写入 | 不允许模型候选改写 | 不能由结果改门禁 | 不能由结果改门禁 | 按原人工决定流程 |

被测 Agent 在测试时收到当前任务 query 和合法工具结果，这是正常执行；它不能收到 gold/未来观察/裁判判词。需要临时拿 query 的 runtime 身份，与可以生成下一版 Prompt 的优化进程分开；受限 trace 不能自动回流给候选生成者。

## 3. EVAL-33 工程实现切片

1. **公开 manifest 和受限 payload 分开**：开发仓库只存集合 ID、协议/版本、数量、分层汇总及不含题目内容的摘要；query/gold/逐题 trace 放保管方控制的存储。SHA 证明封存后未变，不能证明未见或正确标注。
2. **独立身份/执行入口**：生成/验证/盲测各自受限读取凭据；无共享可读目录、管理员 DSN、日志正文、缓存或 Langfuse payload 出口。读取接口投影允许字段，不把全部案例 JSON 直接交模型。
3. **文档关联分组**：DB family_id 是基础；合并版本、原文/译本/转载、同成分等价仿单、指南直接派生及中英文孪生。争议保守同组或暂不纳入；分组决定留理由/来源。
4. **近重复检查与暴露账本**：精确内容哈希、规范化文本重复以及经预登记的方法检查近重复。自动检查给候选和原因，不能单凭未命中断言未暴露。核查历史 query、检索证据、生成/裁判材料及优化 Trace 的实际可得范围；未知仍排除或 provisional 单列。
5. **候选锁定和结果出口**：先锁定单一候选/基线/事实条件/rubric/分母/轮数/种子/停止规则/授权；验证只给白名单聚合诊断。小样本切片也可能还原题目，应在协议中规定最小聚合规则并测试，不能任意打印细分内容。
6. **边界验证和审计**：先用完全公开的合成 canary 数据验证正负访问、错误凭据、路径/跨环境、日志/缓存/telemetry、失败/恢复和候选修改评分器拒绝；通过后才接真实封存数据。合成 canary 不是盲测题。

协议中的正式保管角色、存储方式、近重复算法/阈值和汇总最小规则仍待下一实现切片具体化；必须在接触新题之前确定，不能测完再决定。此文没有声称提供了 ACL、runner、暴露扫描或自动判定能力。

## 4. 暴露账本必须记录什么

每条事件保存：事件 ID、时间、集合/任务或文档关联组 ID、访问者与角色、暴露层次（来源全文、query、gold、输出、逐题判词或聚合）、目的/本轮候选版本、证据回执以及后续资格处理。

来源全文在 RAG 运行时可检索，不等于优化者已看过测试 query/gold；但历史失败与同家族派生题的开发接触影响隔离资格，不能只看文件是否直接命中 gold。无法穷尽旧暴露时诚实保留 unknown，不填 false。

首次正式盲测前，保管流程登记来源关联组/许可证、题目/标注 hash、真实复核者和暴露审计。>=200 唯一任务不等于 200 个独立家族；报告家族数与相关性，不把改写/孪生或同题三轮凑成额外独立样本。

揭盲后用于修复的题或派生关系进入回归资料，下一候选改进声明用新未见集合。三轮锁定配对属于同一个批次，不能看第一轮后改候选继续另两轮，或挑最好一轮报告。

## 5. 当前只有所有者和模型时怎么做

所有者可以担任保管人，用受限出题/评测进程辅助，开发助手仅接触公开规则、manifest 和允许汇总；是否有第二独立人工仍如实标为缺口。仅再开一个能读同一仓库/日志的模型会话不满足技术隔离。

如果所有者没有合适的保管存储或不便参与封存，先完成隔离机制与公开合成案例验证，真实盲测继续待定，不把开发案例改名成盲测。实际保管安排在 EVAL-31 接真实资料前提出可审核方案并请所有者决定；本轮没有要求创建账号或连接外部存储。
