# EVAL-33：近重复与历史暴露检查方法

- 日期：2026-10-14；版本：v0.1；编写/自审：Codex，不是第二独立人工。
- 范围：确定性 query 近重复参考实现、历史扫描计划/回执校验、公开合成自检。**没有扫描真实历史正文，没有新盲测题，没有完成正式阈值校准或真实保管隔离。**
- 依据：[ADR-0012](../adr/ADR-0012-agent-evolution-goals-and-acceptance.md)、[隔离契约](EVALUATION_ISOLATION.md)、[保管提案](EVALUATION_CUSTODY.md)。EVAL-33 保持 IN_PROGRESS；PLAN-02 D-01/D-02 和真实保管安排仍待裁决。

## 1. 要解决的问题与顺序

1. 先核查文档来源、版本、译本/转载、指南派生、同成分等价仿单和已知关联组；由保管流程记录理由与稳定分组。数据库 family_id 只是版本治理元数据，不能证明全部语义关系已登记。
2. 使用现有 `check_disjoint` 拒绝跨集合题 ID、原 query/规范化 query、家族及已登记关联组重叠。
3. 使用本轮 query 相似度参考实现发现需要进一步核查的词面近重复；命中只为 review_required，不自动合并或证明题目语义等价。未命中仍 unknown。
4. 对预登记历史来源逐个留下扫描回执，把开发/候选生成接触的 query、gold、输出、判词及来源关系与待选任务比对，并接入已有暴露账本；无法核实的范围保留缺口。
5. 保管人处理命中、关联与暴露争议，依据固定规则决定排除、分组或 provisional 单列。真实新题只能在保管隔离成立后处理；开发助手只接收获准公开信息及聚合结果。

当前步骤1/4/5没有被这两个纯函数完整实现。本轮不修改已有三组关联示例、258来源候选资格、冻结 query/gold、评分器、原分母或门禁。

## 2. 为什么选这个参考方法

| 方法 | 本轮作用与取舍 |
| --- | --- |
| 原文/规范化 hash | 已有硬重叠检查继续使用，适合完全相同及已定义字符规范化碰撞；不能发现一般改写 |
| 固定字符片段集合 Jaccard | 本轮采用：直接比较输入、无需新增依赖/模型、参数与内容可固定、结果确定；适合作为待复核词面候选 |
| 向量相似度 | 可作为后续语义/跨语言补充；需要固定编码模型、版本、预处理及校准案例，不能拿问答检索成绩代替防污染校准 |
| 近似索引/候选采样 | 可在规模增加后评估；须验证候选遗漏和分批覆盖，本轮不据此宣称所有近重复均已找出 |

本轮不复用 BM25 排名来定义重复，也不让正在调优的检索策略决定评测独立性。字面相似不是医学含义相同：数字、否定、条件改变可能只改少数字符；多个独立问题也可能共享模板。

## 3. 固定算法与参考参数

代码：[screening.py](../../src/medops/evals/isolation/screening.py)。公开参考：[screening-reference-v1.json](../../evals/holdout/protocols/screening-reference-v1.json)。该文件是 **example_only**，未批准为正式盲测策略。

### 3.1 规范化与相似度

- 完全沿用现有 norm-v1：NFC、有限全角 ASCII/单位映射、CJK 提取空白处理和空白合并。保留大小写、标点、数字、否定词、条件文本、上下标；不增加词干化、去数字、删停用词或 NFKC。
- 在规范化后的 Unicode 字符序列上取连续 width 个字符的片段，转成集合。重复片段不加权；不是分词，也不是字形/语义比较。
- 相似度定义为两个集合交集大小除以并集大小。用整数交叉相乘比较阈值，避免边界的浮点舍入；等于阈值也进入复核。
- 原 query hash 相同为 query_exact；原文不同而规范化文本相同为 query_normalized；其他达到阈值的为 query_near。三种原因均只是私有核查材料，原硬分离检查另行运行。
- 不同的短 query 不做模糊评分；相同的短 query 仍发现。空白规范化后为空则拒绝。短文本或译文未命中不能据此放行。

### 3.2 公开合成参考参数

| 参数 | 参考值 | 解释 |
| --- | ---: | --- |
| width | 3 | 三字符片段 |
| min_normalized_chars | 12 | 较短且不同的文本不做模糊评分 |
| threshold | 4/5 | 仅用于合成演练，不是正式重复判定/质量/隐私阈值 |
| max_items_per_collection | 1,000 | 每侧投影数量上限 |
| max_comparisons | 250,000 | 两侧数量之积；超限失败，不截断后返回成功 |
| max_total_query_chars | 1,000,000 | 两侧原 query 的 Unicode 字符总数；规范化和片段构建之前检查 |

正式使用前，保管方应在**已暴露的独立开发校准材料**上固定正负例、参考参数和复核规则，报告误报、漏报及中文/英文/短文本表现。不能接触新封存题后再调阈值，不能把当前合成测试当有效率/召回率证明。

### 3.3 内容、范围与资源绑定

输入是经可信调用方授权的 `RuntimeInput(item_id, query)`，无需 gold。每侧必须与受限 inventory 一一对应，原/规范化 query 摘要均相符；丢题、重复/额外投影、换 query 或篡改摘要拒绝。集合和方法内容摘要绑定到私有报告，方法改变不能复用旧摘要。

全部声明的跨侧组合均执行原文/规范化检查，满足长度条件的才执行模糊比较；compared_pairs不是独立样本数，也不是语义覆盖率。片段在每个 query 上只计算一次，但仍是逐对参考实现。超过输入数量、组合数或原字符量时失败，不输出截断的“无匹配”。大历史集的分批与总覆盖账本尚未实现。

私有报告只有 opaque题ID、两侧清单摘要、方法摘要、匹配原因和分数整数，无 query/gold 原文、片段、自由标签。**私有题ID/匹配关系及 query摘要依然受限，不能直接发给候选生成方。** 本模块不认证账户、不接收任意路径、不公开导出私有配对；真实字段/累积出口沿用 EVAL-33 后续 runner/保管方案。

## 4. 历史扫描需要先登记哪些来源

下表是需要盘点的来源类别，**不是已穷尽的目录清单，也不是已执行扫描**。

| 来源类别 | 要核查的暴露层次 | 具体接线状态 |
| --- | --- | --- |
| 已冻结/开发数据、后继修订与裁决材料 | query、gold、判词及家族关系 | 待按各实际schema写字段适配器 |
| 检索、BM25、裁剪、路由与回放行文件 | query、候选/引用来源、输出及版本 | 待登记全部运行目录与实际字段 |
| 模型生成/裁判输入 | query、gold、输出、判词及真实可见范围 | 待核对输入文件、调用/回执关联 |
| Ask/Skill/MCP受限执行材料 | query、工具结果、来源、输出与执行身份 | 仅在保管环境授权解密；当前纯回执检查不读取它们 |
| Claude/Codex会话及人工笔记 | 实际可见 query、gold、输出、判词、来源关系 | 需要明确原文件/导出来源；缺日志记未知，不虚构或全盘抓取聊天 |
| 私有本地、未入Git、外部或已删除材料 | 按实际内容核查 | 缺失/未授权/无法读取均保留缺口 |

### 4.1 计划和回执契约

代码：[history.py](../../src/medops/evals/isolation/history.py)。`HistoryPlan` 预登记每个来源的 opaque ID、文件/受控导出摘要、适配器ID和必查层次。无文件摘要或未枚举的来源不能被悄悄当作已冻结完整计划；先在保管方待办中记录未知。

`HistoryReceipt` 绑定计划、来源摘要、适配器、已检查层次和记录数。checked要求有实际摘要、全部登记层次及明确记录数；允许明确checked的空文件，但没有回执不等于空文件。缺失回执、missing/unreadable/unsupported/not_selected均为 unresolved；额外、重复、错误计划/适配器或已完成来源摘要/层次不符直接拒绝。

适配器ID `dataset-fields-v1 / retrieval-fields-v1 / execution-fields-v1 / conversation-fields-v1` 是本轮约定的接口标识，**没有对应真实解析器实现或版本准入证据**。receipt不能由候选模型自行填并作为扫描证明。可信保管流程还需核验实际解析器、签发身份与源文件完整读取。

`declared_scope_status=complete`只表示该计划内的回执齐全；`qualification=unknown`与`historical_scope_exhaustive_verified=false`始终保留。它不能证明真实历史全部枚举、内容实际读取、未出现暴露或已经满足正式盲测条件。

### 4.2 后续真实适配器的强制行为

1. 人工/保管核定来源范围、格式、字段白名单及读取身份，不接受模型提交的任意路径；内容先校验摘要，变化则停止并版本化重新登记。
2. 按已核验schema读明确字段，不递归收集所有字符串。实际映射包括query、原query hash、文档/家族/关联组、生成材料及访问角色/用途/层次；不把新query/gold回流给开发方。
3. 全文件逐记录解析；坏行、缺必查字段、解密失败、文件/记录/字符限额、超时或取消均拒绝“checked”。保留未完成范围，不跳过后写完整回执。大文件分批要绑定原摘要及全部分片，无成功分片替代总覆盖。
4. 保管审计先于读取/披露；不把错误对象、SDK日志、正文或私有匹配关系写开发遥测。读取失败仅给固定错误码与受限回执。
5. 原ID/精确及norm query碰撞、家族/关联组、字面近重复分别留证；相似改写、译文、指南派生或历史关系还需核查，未命中不改为 clean。
6. 将已证实的开发/候选生成接触记入已有 `ExposureEvent`/账本，绑定真实角色、用途和原证据回执。runtime正常执行与下一候选生成环境分开，不能伪造访问者或把扫描本身叫独立人工。

本轮不读取会话日志、历史运行正文或受限数据库载荷；因此没有历史暴露的实际统计，也没有将258来源候选升级为合格未见来源。
