# EVAL-33：真实盲测保管与部署提案

- 日期：2026-10-12；版本：v0.1；**可审核提案，尚未选择环境、创建账户或部署**。
- 依据：[ADR-0012](../adr/ADR-0012-agent-evolution-goals-and-acceptance.md)、[隔离契约](EVALUATION_ISOLATION.md)、[当前任务](../CURRENT_TASKS.md)。编写及自审：Codex，不是第二独立人工。
- 本轮只实现离线聚合出口及公开合成核验。需要所有者决定的只有真实保管安排；不是再次索要已批准场景、实验自动激活或普通代码修改许可。

## 1. 为什么需要这项决定

当前开发助手可读取仓库和本机开发凭据。同一账户下的新目录、另一个聊天窗口，或者开发者能管理的 Docker 容器，均不能证明开发者无法读取封存题。应用层 `ReadGrant` 是数据契约，不是账户认证；由模型自己填 `role="holdout_evaluator"` 不应产生授权。

推荐让**所有者控制一个开发助手无凭据、无管理权限的独立环境**，承担出题、封存和锁定批次评测。所有者可用受限模型辅助，但仍只有一名真实人工；不能因此把第二独立人工字段改为 true。未选定环境前，只推进公开合成数据、算法和契约，不把新题保存到本仓库或发送到本会话。

这里的“独立”指访问与候选生成隔离，不保证模型训练中从未出现官方文档，也不保证医学标注正确。历史暴露、文档关系和复核资格还须另外核查。

## 2. 两种可执行选择

| 选择 | 所有者需要提供 | 可以推进什么 | 必须披露的限制 |
| --- | --- | --- | --- |
| A，推荐：所有者控制独立保管环境 | 环境类型及管理员归属；开发助手不持有访问密钥/主机管理权；后续只给公开配置和检查回执 | 先部署受限身份、存储、锁定 runner 和 canary，边界通过后准备真实新题 | 没有第二独立人工仍 provisional；实际配置、日志出口、备份与恢复须验证 |
| B：暂缓真实盲测 | 无需新环境 | 继续近重复方法、历史扫描方案和公开合成验证；PLAN-02 批准后可做开发场景实现 | EVAL-31/EVAL-36 保持未完成，不能声称 S3 在未见题上提升 |

独立云账户/机器是部署候选，不在本轮购买或接通。当前电脑的新普通用户只有在实际权限核验后才可能减少误读；若开发助手仍有管理员、宿主磁盘、Docker daemon、备份或可提权权限，不满足 A。不能凭目录权限或容器名称宣布完成。

选择 A 以后再按实际提供方形成部署清单；需要费用、账户写入或模型调用的动作分别授权。选择 B 不取消 Agent 目标和已确认盲测原则，只延后真实盲测。

## 3. 身份和资料流

| 身份 | 输入 | 允许输出 | 不允许持有 |
| --- | --- | --- | --- |
| 开发/候选生成 | 已暴露开发失败、合法业务事实、公开规则及允许汇总 | 可检查的 Prompt/声明式 Skill/允许策略候选 | 验证及盲测 query、gold、逐题结果，保管管理员权限 |
| 保管/出题 | 获准来源、分组及暴露资料、出题标注材料 | 公开 manifest；绑定锁与协议的受限授权 | 生产策略写凭据；用新题挑候选的权限 |
| 优化验证 | 固定候选、验证任务与评分材料 | 预登记白名单聚合结果 | 最终盲测题、评分器/门禁写权限 |
| 最终盲测评测 | 锁定两臂、封存任务及评分材料 | 批次完成后的聚合结果和受限保管回执 | 调整候选、评分器、生产门禁/指针的权限 |
| 被测 runtime | 当前一道 query、当前用户 ACL 下的合法检索事实 | 回答及受限执行材料交评测器 | gold、未来题、其他轮逐题分数、保管存储及生成下一候选的凭据 |

这些是受限进程角色，不代表已经实现多个自主 Agent。凭据由可信服务端认证并映射到角色；模型参数、请求正文中的 role、UUID 或摘要不能当认证依据。运行时获取当前 query 是正常测试输入，这个进程必须与生成下一候选的环境分开，受限 trace 不能自动回流。

## 4. 存储、锁和日志

1. **分开保存**：公开 manifest 进开发仓库；私有 inventory、query、gold、逐题判词、原始 runtime 记录留在保管环境。query 读取凭据与 gold/评分凭据分开，不能只把完整案例投影后仍给 runtime 同一个可读文件。
2. **运行前锁定**：基线/候选内容、事实与索引条件、rubric、评分器、协议、题目清单、指标 ID、适用题分母、轮数、停止与失败处理、出口最小数量由保管流程预登记。当前 `EvaluationLock` 只有五项摘要，完整 runner 还须绑定以上运行条件，不能宣称现有 DTO 已覆盖它们。
3. **防止换规则**：配置和评分器对 runtime/候选生成只读；结果不能反过来改协议。`ReleaseGrant` 绑定具体结果摘要，但目前不认证签发者，也不证明策略在运行前已冻结；实际服务端要拒绝自签 grant 和中途替换 policy。
4. **禁止共享出口**：不复用开发 `.env`、管理员 DSN、正文 Trace 项目或 cache namespace。禁止 request/response body、异常对象、SDK debug、crash dump、重试日志将受限材料发到开发账户。保管端必要正文按最小权限保存；开发遥测只传固定元数据。
5. **账户与网络**：密钥不进 Git/聊天/镜像；给最小权限、独立归属、撤销机制。需要模型/检索的网络只按批准端点开放；模型调用也会传送当前任务和评测材料，应核对供应商配置与真实数据授权，不能称外部模型完全没有接触题目。
6. **审计先于披露**：可信入口认证、核对锁和预登记范围，先持久化访问/导出授权回执及暴露事件，再给 runtime 输入或导出内容；写入不确定、外部可信头不符或权限未知则失败关闭。纯投影函数不会自行追加账本；该编排尚未实现。
7. **可信头与备份**：JSONL hash 链和 `LedgerHead` 分开保管，外部回执由所有者受控位置保存；签名/不可变存储按部署方案确定。当前原语无签名、WORM 或备份承诺，不能把文件 mode 0600 等同不可篡改。
8. **恢复**：明确保管人、备份验证、保留期限和恢复演练。fsync/网络故障后的未知状态保留；按外部回执核对后处理，不能删行、重置链或重新生成题来掩盖暴露。无法确认恢复完整性时停测、标为 unknown。

实际使用 PostgreSQL/对象存储或其他托管存储取决于环境。PostgreSQL 事务利于运行锁/授权/回执原子化，但管理员仍能读数据；对象存储版本与不可变策略利于封存，但仍需身份、签名和恢复治理。当前离线 JSONL 只用于检查基础失败路径，不提前选定生产保管技术栈。

## 5. 结果出口的具体规则

当前 [aggregate.py](../../src/medops/evals/isolation/aggregate.py) 支持**整个固定集合、已登记二值指标、两臂、全部登记轮次**的传输校验：

- 导出只含固定 UUID、集合/锁/策略摘要、任务/家族/轮次数及允许指标的 passed/failed/unknown 总计；不输出 query、gold、题 ID、逐题结果、自由文本标签、trace 或私有行结果摘要。
- `min_tasks/min_families/min_cell_tasks` 必须显式提供。合成 canary 的 20/2/5 仅测试，不是正式 200 任务要求的替代，也不是已批准隐私阈值或质量门槛。正式值要运行前预登记，不能测后调值使结果通过。
- 只接受 complete 批次；矩阵必须覆盖每个任务 × 每个登记指标 × 两臂 × 每轮，缺失/重复/额外行一律拒绝。unknown 留在分母，不能通过不提交超时行提高成绩。cancelled/failed/running 批次不能导出成绩；运维只可给固定终态和受限故障回执，不泄露逐题内容。
- 任一非空结果格的唯一任务数或已登记家族数不足，**抑制整个指标的两臂计数**，不只隐藏一个稀有格后留下可反推的补集。不输出抑制原因或该指标其他总计。零格允许；所有结果为通过并不自动证明资格或医学正确。
- 三轮是重复观测，不变成额外独立任务；不提供任意子集/家族/单题/单轮查询。单个 grant 锁定一份结果，改行不能复用；真正的签发服务还要限制再签、累计导出、跨批次交叉差分和适应性查询。

**不是完整评分器或统计分析。** 当前每个指标假设适用于全部任务；N/A、逐 claim 指标、延迟、费用、配对 CI、目标/非目标切片尚未接入。不能填 unknown 代替不适用，或用本模块替换已冻结评分口径。后续应按预登记、互不随结果改变的适用集合绑定明确分母，再实现相应分析；EVAL-32 rubric 仍 BLOCKED。

这套抑制规则减少直接逐题/稀有计数出口，不提供差分隐私或“不能推断任何个人结果”的数学保证。已知其他标签、多个批准批次/指标和标签相关性仍可能推断。真实发布要审核允许统计及累积披露，不能仅凭一次 canary 通过说部署防泄漏完成。

## 6. 接真实题前的部署验收清单

下面均是待执行的部署检查；当前只有离线对应测试，不能勾为实际通过。

| 检查 | 正例 | 必须拒绝/失败关闭的反例 |
| --- | --- | --- |
| 实际账户/存储 | 保管人可写封存；合法评测可按角色读 | 开发身份经文件、管理员 DSN、备份、容器/主机管理入口读题 |
| runtime 投影 | 一次只拿当前 query 与合法事实 | gold、未来题、逐题判词，越权文档或自称审核角色 |
| 锁与评分器 | 固定内容摘要的两臂可运行 | 候选修改 rubric/评分器/分母/身份/策略或换候选继续下一轮 |
| 出口 | 全部轮次完整后按登记字段导出 | 部分批次、小集合、任意子集、未知指标、缺行、复用旧 grant 修改行 |
| 日志/缓存/模型 | 保管端受限材料，开发端 metadata-only | 正文经 Trace/SDK 异常/共享 Redis/调试或恢复日志流出 |
| 审计/恢复 | 可信头、授权回执和备份一致 | append/fsync 不确定仍放行，丢账本视作无暴露，重置链冒充未见 |
| 撤权与环境 | 已撤销凭据拒绝，实验身份仅写实验资产 | 保管/runtime 写生产指针、旧 token 继续读取、开发账户控制签发 |
| 费用/停止 | 单次批准范围、总预算和取消按既有 Harness 执行 | 通用“继续”、月余额或失败重试成为新的付费授权 |

先用已公开的合成 query/gold 标记运行这些检查，收据不带真实题。失败须先修复复测，再决定能否接真实新题。不能用 CI 内能读所有测试文件的单用户进程冒充部署隔离正例。
