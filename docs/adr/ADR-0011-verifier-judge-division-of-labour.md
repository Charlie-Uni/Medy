# ADR-0011：DEC-003 Verifier 支持度判定——规则与模型的分工，以及判定模型档位

- 日期：2026-09-23
- 状态：分工**已决**（决策人 2026-09-23："按照你建议的改"）；判定模型档位**待锁定**（OpenAI 三臂在同一子集上实测后回填，见 §4）
- 决策来源：[实现记录 53](../reviews/2026-09-23-implementation-53-dec003-verifier-arms.md)；基线 5.4（数字规则优先、矛盾升级）、§10 DEC-003；ADR-0010（运行时厂商 OpenAI）

## 决策

1. **分工（`medops.verification.verifier.DEFAULT_POLICY = "polarity_only"`）**：配置了判定模型时，确定性规则只单独裁两类结论——(a) 否定极性矛盾：陈述与证据同值或同文本但否定线索计数不同（`不得/禁用/not/unless…`，对齐窗口计数）；(b) 同极性整句包含：陈述规范化后整句落在证据的一个句子内。其余一切（含数值精确匹配、数值不一致、要素级包含、词元重叠）交模型做一次陈述级判定。规则不再单独把"证据中唯一的异值"判为矛盾。
2. **无判定模型时**（离线工具、单元测试、`judge_model_id=None`）沿用 `rules_first`：规则 → 要素包含 → 词元重叠，未决记 not_supported 并由 Answer 节点丢弃该陈述（fail-closed）。
3. **矛盾一律升级、not_supported 陈述一律删除**（基线 5.4 第 4 条）不变；模型判定的 `contradicted` 与规则判定的同权。
4. 判定模型经 Model Gateway、单组一问、JSON schema、`purpose="verify"`；模型 ID 与 `VERIFIER_VERSION` 一起进入 Trace 的版本集。

## 依据（记录 53，2,076 对；模型臂与政策推演在 300 对种子子集）

- 规则臂（`support-rules-v1`）：准确率 91.0%，错接受率 5.2%；否定翻转 90%，数值翻转 71%，同文档负例 85%。
- Claude Haiku 4.5 / Sonnet 5（订阅 CLI）：准确率 94.6% / 95.7%，错接受率 5.3% / 4.8%；否定翻转 88% / 85%（**低于规则**，漏判理由全是"证据逐字包含"），数值翻转 100%，同文档负例 87% / 94%。
- 分工推演（同一子集、已记录的模型判定）："规则能决则决"错接受率 6.1–6.6%（最差）；"全交模型"4.8–5.3%；**`polarity_only` 3.9–4.4%（最低）**，模型调用占 77%，准确率比全交模型低约 1 个百分点。选择依据是错接受率（不支持/矛盾被判支持）——它直接对应 M2-16 的引用准确率与"无依据不补医学常识"。
- 两档 Claude 模型差 1 个百分点，提示便宜档可能够用；档位由 OpenAI 三臂决定，不外推。

## §4 判定模型档位（待回填）

候选 `gpt-6-luna`（$0.10/$0.50 每百万 token）、`gpt-5.4-mini`（$0.75/$4.50）、`gpt-6-sol`（$2/$10），同一 300 对子集、`run_gateway_arm.py --mode llm` 与 `--mode hybrid`（即本 ADR 分工）。选取规则（预登记）：取错接受率不高于最优档 +1 个百分点、准确率不低于最优档 −2 个百分点的最便宜档；并列取更便宜者。回填后锁定 `HarnessDeps.judge_model_id` 的生产默认值。

## 后果

- 运行时每条陈述约 77% 会产生一次判定调用；按 gpt-6-luna 价目一次主集端到端的判定成本约 0.3 美元，gpt-6-sol 约 6 美元（ADR-0010 上限 30 美元/月内）。
- `VERIFIER_VERSION` 升为 `verifier-v2+support-rules-v1+polarity_only`；已冻结数据集与评测报告不受影响，M2-16 门禁按新版本跑。
- 规则臂的两个已知弱点（同值不同语境、数值多值）由模型承接；模型的已知弱点（删否定后的"逐字包含"）由规则承接。任一侧口径变化需重跑记录 53 的对比。
- 待办：把 `polarity_only` 的错接受率纳入 M2-16 报告；DEC-003 数据的局限（陈述为逐字条款、矛盾为合成）在安全集（M2-15）建立后用真实改写句复验。
