## 2. 背景与目标差异

原描述同时包含固定 Harness 链路和“自动生成 Prompt、Rule、Skill 或检索参数候选”的受控 Loop。当前实现已有固定 RAG 图、五类 Skill、检索/缓存/观测和候选发布基础；模型按结果自主选择工具、模型生成 Prompt/Skill 内容和新 Skill 实际加载仍有缺口。历史 M4 框架完成记录不能证明上述新能力已经具备。

| 范围 | 原实现/验收容易产生的歧义 | 本轮拟明确的目标与证据 |
| --- | --- | --- |
| 运行时 Agent | 固定图、条件升级或模型路由被当作自主行动 | 模型选择允许工具，观察结果后补检索/调整行动/澄清/停止；不同情境产生合理不同路径 |
| Harness | 固定节点顺序被理解为所有任务唯一业务路径 | 保留快速固定链，增加有界动态路径；最终证据、安全、权限、预算及审计仍必须通过 |
| Reflect/Adapt | 规则归因、needs_author 或手写候选被当作模型自进化 | 模型基于开发失败案例生成真实内容差异，并有调用来源、失败记录和可执行候选 |
| Skill 版本 | 新版本标签/数据库记录等同于新能力 | 声明式 Skill 定义实际改变工具组合、条件或 Prompt；加载、版本绑定和回滚可验证 |
| 成效 | 开发集/回归集提升被当作泛化改进 | 第三阶段改进声明须有未见盲测结果；机制完成和效果通过分别登记 |
| 自动激活 | 实验采用与生产发布边界不清 | 自动激活只写实验环境；生产保留原人工签字、正式门禁、灰度及回滚 |

保留模块化单体、LangGraph、现有 RAG/Skill、BM25、Redis、Langfuse 和模型路由。首版 Skill 使用受约束的声明式定义；模型不能修改硬安全规则、权限、评测器或批准机制，不执行任意生成代码。基座模型训练不属于本轮“自进化”。

**已确认的编号解释：** 沿用台账标识，第二阶段指 `S2 首个业务 Agent`，第三阶段指 `S3 Prompt 自进化`；S0 为目标/验收准备、S1 为必要执行修复，S4/S5 为扩展与整体验证。所有者已回复“按 S2 / S3 理解”。

第二阶段必须同时具备以下证据，任何一项未通过都不能启动该阶段实施/集成或试跑；任务拆分或称为“演示”不能绕过。S0 的契约/假数据用例准备不等于进入第二阶段。

1. **ARCH-04 自审通过并有回归证据**：每次模型调用的 Trace/call/attempt/reservation/结算回执可关联；并发成功、失败、取消、预留拒绝与结算异常的费用不会串账，估计与实际费用分开。
2. **ARCH-11 自审通过并有回归证据**：翻译、规划、生成、判定、结构化输出、重试/回退全部受同一执行预算约束；调用前预留、调用后结算、超限停止，不能只限制单次 max_tokens 或月度总额。
3. ARCH-11 依赖 ARCH-04；相关租约、历史语义、最终判断、审计与回放前置仍按台账满足，不能用这两项替代其他正确性要求。

## 4. 自动激活的环境边界（已确认）

- 允许：获准实验批次内，合格候选自动切换**实验**策略/Skill 指针，验证下一次实验请求实际采用新内容，并能回滚。
- 隔离：实验使用明确环境标识、独立策略指针和受限服务身份；实验角色无生产指针写权限。API、worker、缓存 namespace 和审计记录都须能区分实验/生产。
- 拒绝路径：缺少/伪造环境标识、生产 DSN 或凭据误接、跨环境候选与版本冲突都拒绝；即使实验评分合格也不能自动写生产。
- 生产：继续要求符合原门禁、真实人工签字、初始灰度不超过 10% 和可审计回滚。批准后的部署操作可自动执行，但不能省略候选级人工发布决定。
- 原 EVOL-09 的“是否扩到生产自动批准”待决项关闭为**所有者已决定限实验环境**；本次迭代不继续提议扩大生产自动批准。

## 5. 盲测资格与改进声明（原则已确认）

盲测是相对于本轮开发/候选优化未见，不声称基础模型预训练时从未见过公开文档。至少满足：

1. 开发失败案例、优化验证集、最终盲测集分离；按文档家族/版本和近重复关系隔离，保存来源、暴露账本和集合哈希。用于调参的题不能重新命名成盲测。
2. 生成/调优方在候选锁定前不能访问盲测 query/gold 或逐题结果；运行 Agent 在正式测试调用时接收其测试 query 是正常执行，不能把答案回馈给候选生成者。
3. 先锁定单一待检候选、对照版本、rubric、分母、样本/分层、随机轮数和判据，再由独立评测进程运行。候选筛选使用优化验证集，不能用最终盲测挑多个候选。
4. 同一锁定候选预登记的三轮是一个评测批次；查看盲测结果后据此改候选，该集合转为已暴露回归资料，新一轮改进声明需要新的未见集合。
5. 独立流程/模型裁判不等于第二独立人工。目前只有所有者与模型，标注独立复核缺口继续如实披露；允许符合隔离条件的 provisional 盲测报告，不能宣称原独立人工门禁已通过。

没有合格盲测或未运行时，只能说“候选生成/加载/回滚机制已验证，改进效果待盲测”。可以单列开发诊断分数及局限，不能据此声明“自进化提升”“泛化改善”或把第三阶段效果门标为通过。该原则同样适用于后续 Skill 改进声明。

### 5.1 题目从哪里来、由谁接触

当前[盲测准备说明](../../evals/holdout/README.md)尚无冻结盲测题，200 题是新建任务，不是已存在数据集。现有家族盘点中 258 份 active 文档未出现在所扫描的主集 gold/无答案和安全显式字段里，仅是待排查候选；它们可能已经进入历史检索或属于译本/近重复，不能直接视为未见来源。

优先从已通过 [ADR-0003](ADR-0003-corpus-source-license-policy.md) 许可准入的 FDA、EMA、ICH、TFDA 等现有官方原文中选取，按实际任务归属 MA/PV/CO；不足时再按原白名单和许可签字流程补文档。官方身份本身不代替逐文档许可。

出题材料与任务类型：

- 原文事实/条款题：围绕版本、适用条件、共同必需证据和指定来源设计，gold 有原文页码、区间和可接受证据组。
- 多步业务任务：以原文为判定依据，配合明确标记的合成事件/操作记录，预期包含工具使用、缺信息澄清、证据完整性和升级；不使用真实患者资料。
- 无答案/冲突/权限反例：根据冻结事实库、身份和日期构造并核验，不能只由模型主观断言无答案。

真实失败案例可启发任务类型，但已经用于优化的原题、改写、孪生和同家族派生题进入开发/回归，不计入盲测。现有 615 条主集不重新命名成 200 条未见题。封存 query/gold 由受隔离的出题/保管流程管理，可用模型辅助草拟并由所有者按规则复核；优化方只看规则、清单元数据/哈希和获准汇总。当前没有第二独立人工，该缺口继续单列。不能让同一优化上下文看完题和答案后仍声称对它盲测。

## 6. 验收口径与剩余调整

### 6.1 保留的门禁

原 QA Recall@5 ≥85%、引用准确率 ≥95%、失效版本引用 0；正确拒答 ≥95%、越权拦截 ≥98%、高风险升级召回 ≥95%；普通 QA P95 ≤8 秒、复杂 Skill P95 ≤15 秒、同等质量 Token 降低 ≥25%，保持原版本和分母。新增多步任务需在 EVAL-32 预登记工作量/时限，不能通过重分类掩盖原未达。

原生产 Loop 仍需 ≥200 唯一历史 Trace、安全集全量、随机流程 3 轮、配对比较和 bootstrap 95% CI 报告；目标 +5pp、非目标下降 ≤1pp、安全不下降。**现行基线只把 CI 作为必报项；本草案不追溯改写该规则。**

### 6.2 第三阶段盲测：方案 A，结合“不强制固定提升幅度”补充

- 建立至少 **200 个唯一盲测任务**的版本，建议目标/非目标各 100；分部门/文档家族分层，各报告切片满足原适用样本规则。目标组指本轮优化希望改善的任务类型，非目标组检查其他原有能力是否退步，不按候选得分事后分组。具体来源/分层在 EVAL-31/33 准备后冻结；200 是设计下限，不是统计功效保证。
- 原回归/安全集另跑；已有安全集如已参与调优，必须标为回归安全证据，不能计入“未见盲测”数量。原 ≥200 历史 Trace 要求与这 200 个新盲测任务分别满足，不能相互替代。
- 候选与基线在同一盲测任务上各跑 3 轮；200 题 × 2 版本 × 3 轮约 **1,200 次任务执行**，不是 1,200 个独立题，也不是 1,200 次模型调用。每个 Agent 任务可能多次调用模型，裁判和原安全/回放另计；具体费用另行预估与授权。
- **不设固定 +5pp 幅度硬线。** 完成机制、完成有效盲测和有证据的正向改进分开记录。要声称目标成功率改善，配对差必须为正且预登记 bootstrap 95% CI 下界 >0；非目标下降不超过 1pp，安全不下降。CI 跨零/退步也必须报告，可以完成评测工作但不能声称已证明提升。
- CI 重采样/汇总方法在首次运行前登记，保留题目配对、重复轮次和文档家族相关性；不能把同题三轮或同家族多题当独立样本放大证据。效率改善声明另需预登记质量不退步与对应成本/时延判据，不能替代成功率改善声明。
- CI 判据作为**新增盲测改进声明门**；原生产回放 +5pp 的是否修改仍待 §8 决定。开发/回归结果不能替代盲测。
- 报告目标/非目标质量、引用支持、完整性、误拒答、系统失败、时延、Token 和费用。样本不足、CI 跨零或缺人工证据时明确限制，不选择最好的一轮。

v0.1 的替代方案 B（只报 CI）未被选择；A 的固定 +5pp 部分按所有者补充移除。该方案增加样本、标注和试验成本，但选择方案不等于付费授权。本轮不生成盲测题、不看盲测答案、不运行实验；新增 EVAL-36 承接实际盲测，EVAL-35 继续负责原正式回放门。

### 6.3 完成状态

工程子项、开发试跑、有效盲测完成、改进声明是否获支持和生产发布分别记录。S3 的研发交付要求机制证据与有效盲测报告齐备，不要求出现固定幅度提升；盲测不支持改善时可报告工作完成、效果未证实，不能写“改进验收通过”。没有盲测则效果待验证；没有合格候选时保留旧版，原生产发布门未获变更前继续适用。

## 7. 付费授权与每轮自审（已确认）
