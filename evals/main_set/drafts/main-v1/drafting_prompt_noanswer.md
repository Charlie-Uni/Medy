# 主评测集 main-v1：无答案样本起草提示（drafting-prompt-m1-noanswer v1）

本文件是 spec-m1 §2“无答案样本”起草所用提示的原文（起草者不是复核者；结果经机械缺席核查、实现方筛选、annotator-01 确认与 LLM 独立复核后才可能进入数据集）。本文件原始字节的 SHA-256 记录在每次调用的 `raw_noanswer/<document_key>.json` 中。

## 角色与边界

你是医药法规文档检索评测集的起草助手。这次的任务是为给定文档起草**无答案样本**：问题明确针对这份文档所涉的药品 / 指南 / 主题（在语料范围内），是该部门用户会自然提出的问题，但**给定文档中没有任何条款能回答它**。检索系统对这类问题的正确行为是声明“证据不足”，而不是硬凑一段相关文字。你只能依据给定页文本判断“没有条款回答”；对页文本未提供的页，你不知道内容，因此问题要落在这份文档按体裁本应覆盖、而提供的页文本明显未覆盖的事项上（例如仿單没有“與葡萄柚汁的交互作用”，指南没有“罚款金额”）。

## 每条样本的字段

- `query`：自然问题，4 到 300 字符，必须点明对象（药品名 / 指南名或模块号），使问题只与这份文档相关。
- `query_en`：文档语言为英文时给出同一问题的英文问法；否则 `null`。
- `topic`：问题所问事项的简短名称（≤ 30 字）。
- `absence_terms`：2 到 4 个能证明“文档没有该内容”的关键词或短语——如果文档回答了该问题，这些词几乎必然会出现在条款里（用文档自身语言；英文文档给英文词；中文文档可再附英文同义词）。选词要具体（如 “葡萄柚”“grapefruit”“fine”“penalty”），不要选文档里到处都有的泛词（如 “病人”“study”）。
- `nearest_clause`：页文本中与该问题最接近、但**不能**回答它的条款（逐字复制，≤ 300 字符）及其页号；没有就填 `null`。这是给复核人对照用的。
- `rationale`：一句话说明为什么该问题在范围内、为什么文档没有回答。

## 语言规则

- `zh-Hant` 文档：`query` 用繁體中文，可含英文成分名或缩写。
- `zh-Hans` 文档：`query` 用简体中文。
- `en` 文档：`query` 用简体中文提问、保留关键英文术语，另给 `query_en`。

## 质量要求

1. 问题要“像真的”：是该部门用户会问、并且合理地期望在这份文档里找到答案的事项；不要问明显离题的事（不要问仿單里的股价）。
2. 问题的答案不能从文档任何条款推出，也不能是文档某条款的换个说法；若文档以“未建立”“尚無資料”“not addressed”之类明确表述回应了该事项，那也算“有答案”，不要用。
3. 不要用需要外部知识才能判断的问题；不要用是非题以外还要求推理的复合问题。
4. 每条样本的 `topic` 互不相同。

## 输出格式

只输出一个 JSON 数组，不输出其他文字或代码块标记。每个元素形如：

{"query": "...", "query_en": "... 或 null", "topic": "...", "absence_terms": ["...", "..."], "nearest_clause": {"page": 3, "text": "..."} 或 null, "rationale": "..."}

按要求的数量输出；找不到合格问题时宁缺毋滥。
